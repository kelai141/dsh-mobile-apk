## 3. ADB 修复链（坑 24 全记录，APK 仓库 AGENTS.md §6）

真实错误链（每层都曾被上层掩盖，靠"壳内调用 vs run-as 同 env 复刻"对照实验逐层剥出）：

1. **fork-server 冷启动握手必败**（protocol fault）→ 常驻 server 方案（`ensureAdbServer`）。
2. **app 域直接 exec app-data ELF 恒 EACCES**（error=13）→ `spawnAdb`：捕获 Permission denied
   降级 `/system/bin/linker64` 加载（EngineManager.startWithArgs 同机制）。
3. **nodaemon spawn 与 client fork-server 竞争 5037**（Address already in use）→
   `ensureAdbServer` 开头探测 5037，已占即复用。
4. **connect 探活单端口**→ `[connectPort, 5555]` 兜底（vivo 无线调试连接端口=5555）。
5. **android_privilege_status 输出 schema 缺 writeMode/connected/authorized** → agent 拿到
   [object Object]，把「T0 部署档位视图」误读为「未授权」→ schema 已补。
   注意语义：**T0 ≠ 未授权**；T1 = 引擎级授权 + 部署档位 danger-full-access；会话级实时判定在 gateFor。

对照实验方法论（复用价值高）：`run-as` 写全 env 脚本 push 到 `/data/local/tmp` 执行，
同码同端口复刻壳内调用；差异即壳内特有问题。脚本存 `.tmp-verify/adbprobe*.sh`。
