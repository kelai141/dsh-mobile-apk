## 三个被排除的候选（有数据支撑）

1. **前缀重写换语言**：慢在 syscall 本身（每次几毫秒），不在解释器。
2. **目录 `mkdirs` 缓存**：实测 1 260 244 ms → 1 292 351 ms，**没有收益**。
   `mkdirs` 在目录已存在时本来就是 stat + 早退，缓存省不到点上。
3. **`ArrayCache.getDummyCache()` 禁用 xz 缓存**：仍然 OOM，主项是队列排队内存。

## 未覆盖（必须明说）

- **arm64-v8a 缺真实设备**。#1707 与 #1713 的 Rust 部分只有编译与 APK 内容检查。
  三台看似可用的云机 `uname -m` 是 `aarch64`、`abilist` 也列了 `arm64-v8a`，
  但 `ro.product.cpu.abi` 与 `/system/bin/sh` 的 ELF `e_machine` 实测都是 x86_64，跑不了 arm64 的 `.so`。
- **#1715 的崩溃率未统计**：单次跑通不等于稳定，低堆设备上需要反复跑。
- **#1717 只有单次测量**，未做多轮。
- **模型回复链路未验证**：验收 AVD 没配模型凭据，ADB 用户层只证到「真实输入与提交路径可用」。
- **插件矩阵未覆盖**：本轮没跑第三方插件的真实工作流。

2. 在缺 #1715 限流修复的分支上测解包，测到 OOM 崩溃。
