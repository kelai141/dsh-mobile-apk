# Cordis 与 Android 原生服务的边界

基线：Harness `0.2.2-rc.1`，提交 `66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`。
本说明记录迁移边界与验收口径。当前没有替换 Cordis，也没有启用新的跨进程服务。

Cordis 的 `Context` 用 Proxy、原型链和 Symbol 表达隔离与继承；`provide` 的对象由当前
fiber 持有，卸载时执行 disposer。`emit`、`bail` 在同一 JavaScript 调用栈里同步执行回调。
因此普通进程间请求无法保留对象身份、回调接收者、同步短路和异常传播。第三方插件继续从
`@deepseek-ai/cordis` 获得这些语义；WebUI 的客户端注册与事件链也继续留在原运行时。

可迁移的部分应由 Android 直接调用 Rust，并在需要与引擎互操作时通过既有插件接口连接。
单次调用提交一批足够大的工作，只返回必要的结构化结果；进程间传输的工作量算入收益。
只在确有调用时加载原生实现，不常驻轮询、不为每个对象事件发送消息。缺少实现时保留
既有路径；原生调用若已开始修改外部状态，不盲目在旧路径重放。

| 候选 | 当前执行位置与边界 | 本轮结论 |
| --- | --- | --- |
| 控制台 PTY 转发 | APK 启动单独的 Node + node-pty 进程。shell 和 PTY 传输可分开保留 | [Rust 设备探针](../scripts/android-native/pty-probe/README.md) 已证明 bionic 路径及局部收益；仍需产品接入和三层验收 |
| 会话查询 | `SessionQueryEngine` 是 Cordis 服务；`searchSessions` / `searchEvents` 已异步，底层排序和搜索已用 Node SQLite FTS5 | 优先测索引构建时的事件提取、同步 SQL 及 GC。可研究由 Android 持有派生索引，先保留 JS 的实时会话和取消语义；仅搬 SQL 或逐事件 RPC 没有足够收益依据 |
| 文件与搜索 | `FileSystem` 的元数据访问可异步，但路径身份、监控回调和写入保护是同一契约；文本搜索已使用 ripgrep | 逐文件跨进程往返会增加工作量。只研究已经量出瓶颈的批处理，不另建通用文件服务 |
| 启动装配 | 依赖扫描涉及包解析和 profile 叠加；Cordis 仍负责插件对象和生命周期 | 先量缓存命中和失效时的启动收益。缓存键需随安装、卸载及热更新失效 |
| 会话压缩 | 已通过 `node:zlib` 使用原生 Zstandard | 仅更换语言没有已知收益；不迁移负责损坏判定和恢复的路径 |

采用原生实现前，在同一 APK 上游 SHA、设备 ABI、数据、插件制品和配置下做交错 A/B。
对跨环境的服务同时测调用耗时、序列化、排队、回传和取消；对 Android 侧独立运行的工作
确认没有引擎或 Node 进程被附带唤醒。记录 p50/p90、两侧总 CPU、PSS/RSS、唤醒次数、
GC 和长时间运行。MuMu 可重复测功能和软件开销；整机功耗需在支持功耗测量的设备上另测。
只有服务语义、WebUI 及第三方插件实际功能都能复验，且端到端开销未恶化，才可替换默认路径。
