# Persistent data and recovery sources

This map describes current APK behavior from source and the embedded snapshot. Private app storage and private SharedPreferences survive an APK coverage upgrade. Android uninstall or Clear Data removes them. Shared storage exports are user-created copies, not canonical engine state. Unknown existing files under `files/home/.dsh` are user data and must be retained unless ownership is proved.

## Runtime and data boundary

| Area | Physical location | Owner / recovery source | Upgrade and recovery rule |
|---|---|---|---|
| Hard runtime | App-private `files/usr` (`usr/bin/node`, `usr/lib/node_modules/@deepseek-ai/dsh`) | APK `assets/snapshot.tar.xz`; optional online runtime archive verified against the manifest SHA-256 and staged by `UpdateManager` | Rebuildable from the embedded snapshot. Online update uses `.snapshot-transaction` and `.snapshot-previous/usr` as its journaled probation source; healthy probe commits and cleans it, while cold-start recovery rolls back an uncommitted swap. |
| HOME seed | `files/home/` | Embedded snapshot | Snapshot transaction seeds missing top-level entries; existing HOME content remains user-owned. |
| DSH_HOME | `files/home/.dsh/` | DSH, Cordis, plugins, user | Mixed Soft and Data. Snapshot refresh merges profiles and preserves user-owned entries; never replace the whole tree as cache. |
| Active profile/config | `files/home/.dsh/profiles/<profile>/cordis.patch.yml`; current web profile also reads `files/home/.dsh/cordis.patch.yml` after profile and bundle layers | User and Soft plugins; `SnapshotUserData.configurationDocument()` chooses active config | Preserve explicit user/provider/model values. The HOME patch is a later persistent Cordis layer and its bytes participate in Soft health composition. Legacy `settings.yaml` may be retained with `settings.yaml.imported` after migration; it is not necessarily the active config. |
| Legacy/imported settings | `files/home/.dsh/settings.yaml`, `.imported` | Historical config importer / DSH migration | Keep migration marker and source file; an imported marker means the old file is not the active configuration. |
| Soft plugins and profile files | `files/home/.dsh/profiles/**` including `node_modules`, plugin code/config and profile metadata | User-installed/model-generated plugins plus shipped profile seeds | Merge rather than directory replacement. Hard/Soft mount manifests below classify mounted entries for failure recovery. |
| Sessions and attachments | `files/home/.dsh/sessions/**`, `storages/`, `attachments/` | DSH session/storage subsystems | Explicitly preserved across snapshot replacement. |
| Workspaces | `files/home/.dsh/workspaces/**` | DSH workspace subsystem and user | Explicitly preserved; includes configuration and user files. `workspaces/incoming` is an intake queue; do not treat all workspace content as temporary. |
| Credentials | `files/home/.dsh/.credentials.yaml`; Android engine auth cookie in `dsh_engine_auth` preferences; legacy API-key files `files/deepseek-key.txt`, `files/dashscope-key.txt` | DSH/provider config, `EngineAuth`, compatibility environment | Secrets. Keep app-private; exclude from ordinary logs/diagnostic exports. Snapshot source strips credentials. Do not assume exported YAML or public export bundles are complete backups. |
| Other DSH_HOME durable state | `.anonymous-user-id`, `.private-layout`, `models-store.json`, `.node-compile-cache`, `.dsh/llm-deepseek/**` | DSH / local runtime | These names are explicitly preserved by `SnapshotUserData`; cache-like name alone does not authorize deletion. |
| Undo history / Safe Mode | `files/home/.dsh/undo-snapshots/**`, especially `auto/` | `dsh-undo-savepoint`, emergency CLI, `SafeMode` | Contains Soft/config recovery snapshots and Safe Mode backups/state. Not a disposable cache. |
| Work-in-progress intake / caches | DSH_HOME plugin-specific paths, `.node-compile-cache`, `models-dev.json` where present | Owning plugin | Clear only with a specific owner/allowlist and recoverability evidence; preserve unknown paths. |
| Logs and diagnostics | `files/engine.log*`, `files/boot-diag.log*`, `files/boot-fail.log`, `files/undo-gate.log*`, `files/diagnostics/**` (all single files in `filesDir`); event log directory `files/log/**` | `LogCollector`, `UndoGate`, startup probes | Diagnostic, rotated/bounded independently; not authoritative user configuration or recovery state. The event log directory is `Documents/dshdata/log` when `MANAGE_EXTERNAL_STORAGE` is granted, otherwise the app-private `files/log` (`LogCollector.currentDir`); `files/dshdata-fallback` is only the intermediate value used when the public Documents directory cannot be resolved, never a log mirror target. Redact secrets. |
| User exports | User-selected SAF document; existing partial exports may use public `Documents/dshdata/exports/**` or app-private fallback | Settings export / diagnostic bundle code | User-initiated copies, not the engine's canonical store. They do not cover the whole DSH tree and are not a substitute for a complete backup. Uninstall-safe full backup (apk #108) is not planned: app-private state is lost on uninstall or "clear data", and that limitation is not worked around in this round. |
| Unknown DSH_HOME item | Any existing `files/home/.dsh/<name>` not classified above | Unknown / user until proved otherwise | Preserve by default, including fields and nested files not understood by current code. |

`SnapshotUserData.preservedNames` currently includes `sessions`, `storages`, `attachments`, `workspaces`, `undo-snapshots`, `llm-deepseek`, `.credentials.yaml`, `settings.yaml`, `settings.yaml.imported`, `.anonymous-user-id`, `.private-layout`, `models-store.json`, and `.node-compile-cache`. The verified current factory archive direct children under `.dsh` are `profiles/`, `settings.yaml`, and `.private-layout`; collision policy is implemented by `SnapshotTransaction` / `SnapshotUserData`.

## Durable recovery records and authorities

| Record | Physical location | Writer → consumer | Meaning |
|---|---|---|---|
| Snapshot swap journal | `files/.snapshot-transaction`, temporary `.snapshot-transaction.tmp`; stage/previous trees `files/.snapshot-stage`, `files/.snapshot-previous` | `SnapshotTransaction` → `EngineManager` refresh and startup recovery | Records a multi-tree snapshot swap for interrupted roll-forward/rollback. Do not clear until recovery has converged. |
| Snapshot identity | `files/.snapshot-fingerprint` | Successful snapshot activation → freshness policy and UndoGate | Identifies the installed embedded snapshot; prevents restoring configuration snapshots from another install generation. |
| Snapshot failure ledger | `files/.snapshot-refresh-failures` | `EngineManager` → refresh retry/failure policy | Bounded failure count scoped by bundled fingerprint; diagnostic/policy input, not content authority. |
| Reverse-migration stage ownership | Sibling `<private-name>.reverse-migration-stage` plus `<private-name>.reverse-migration-owner` beside each migrated directory; interrupted marker writes may leave a uniquely named `*.owner.*.tmp` sibling | `ReverseMigration` → `EngineManager.ensurePrivateDshData()` retry | Requires absolute private/public paths and a private target with a parent. Copy and verify in an isolated sibling before atomic activation. The owner marker is written to a unique temp and atomically renamed into place; incomplete/unrecognized temp siblings are left untouched and do not block retry. A matching owner marker allows retry to discard a partial stage or finish cleanup after activation. An unmarked stage is treated as unknown data and blocks migration without deletion. Non-directory private collisions fail closed; existing nonempty private directories still win and public data is retained under `*.public-backup`. |
| Runtime update transaction | `files/.snapshot-transaction`, `.snapshot-stage/`, `.snapshot-previous/usr`, `.online-snapshot`, `.update-pending`, `.update-pending-at`; legacy `update-stage/`, `usr-old`, `usr-broken` may remain | `UpdateManager` → `EngineManager.recoverInterruptedRefresh()` / `onEngineProbe()` / `rollbackToOld()` | New online updates share the snapshot journal and stage, replace only `usr`, and retain the previous runtime through health probation. `.online-snapshot` binds the archive SHA to the embedded-snapshot SHA so a healthy online tree remains fresh across same-APK restarts; a changed embedded SHA triggers factory refresh. Legacy `usr-old` is not recursively deleted or trusted as ownership proof; legacy probation remains supported and retains its old source. |
| Runtime damage marker | `files/.runtime-tree-damaged` (constant in `RuntimeTree`) | Runtime integrity check → controlled snapshot repair path | Signals runtime-tree damage; verify source constant if changing its spelling. |
| Configuration recovery copies | `files/.snapshot-settings-backup/settings-<timestamp>-<source-name>` | `EngineManager.snapshotSettingsBackup()` → user diagnostics/manual recovery | Keeps the three newest active configuration copies before snapshot refresh; the copy is best-effort and not the active config. |
| Undo observation and retry | `files/.undo-auto-armed`, `files/.undo-auto-done` | `UndoGate` → watchdog trigger/retry-window decision | Armed observation timestamp and schema-2 successful-undo marker containing the frozen install fingerprint + failed patch digest + time. An explicit UI restart clears the marker only after the owned child stops; automatic retry paths do not. Neither file is a user-data backup. |
| Known-good Soft restore pointer | `files/.undo-known-good` | `UndoGate.noteHealthy()` → `UndoGate.execute()` | Two lines: auto snapshot ID + current `.snapshot-fingerprint`. Set only after shell probe reports HEALTHY; explicit-ID restore only. Missing, pruned, or cross-install targets fail closed. |
| Hard mount manifest | APK asset `plugin-hard-manifest.json`, `files/.plugin-hard-manifest.json` active cache, and SHA-keyed online sidecars `files/.plugin-hard-manifest-online-<archiveSha>.json` | `scripts/build-hard-manifest.mjs` scans the final snapshot and records exact `profileEntries`; `PluginMounts.ensureHard()` selects the APK asset or a transaction-authorized online sidecar → `SafeMode`, `UndoGate`, `EngineStartFlow` | Schema 2 binds exact `{id,name}` entries to final archive SHA and separately records packaged-profile identities. Online sidecars combine verified staged `usr` base/web-app entries with the current APK's packaged profile identities; when a full trusted archive has a `home/` entry, its factory profile is required and exact identities are merged after conflict checks. Only complete absence of `home/` permits usr-only fallback. Stage HOME is read only as verified factory input and is never swapped into the user's live HOME; live HOME/user patch and prior sidecar profile identities never establish new ownership. The online transaction marker or committed `.online-snapshot` must match archive SHA and bundled base SHA. Unknown/incompatible marker, missing, malformed, interrupted-swap, or mismatched data makes ownership inconclusive and non-destructive. Sidecars are retained by archive SHA for rollback selection. |
| Required Hard bundle selection | `files/home/.dsh/profiles/web/package.json` nested `dsh.profile.bundles` | `EngineManager.startEngine()` → `PluginMounts.ensureHardBundlesSelected()` on every startup decision | Validates current Hard manifest factory tuples against installed package name/version/ordered patch bytes, then atomically appends missing trusted bundle names. Preserves Soft selections, dependency pins and unknown JSON fields. Missing authority, malformed/ambiguous JSON, unsafe path or identity mismatch refuses startup without writing the profile. Runs even when the snapshot is already fresh; a changed selection requires controlled engine restart. |
| Soft mount manifest | `files/.plugin-soft-manifest.json` | `PluginMounts.noteHealthy()` / `shouldProbeHealth()` → `UndoGate` | Tracks `candidateDigest`, candidate engine-spawn identity/time and bounded probe; then `stableDigest`, exact `stableEntries`, `stableNames`, `stableAt`, and `stableBoot`. The `DSHCOMP2` digest binds ordered verified bundle identities/patch bytes, profile Cordis bytes, and optional HOME Cordis bytes; HOME absence differs from an empty file. Unknown composition may receive a rate-limited diagnostic probe but cannot be promoted. Promotion requires identical composition digest and complete authenticated Cordis inventory on two distinct successful engine spawns 30 seconds to 7 days apart. Every Hard identity must be present; any currently enabled entry/preset fiber must be active; valid `session/list` and `session/modelCatalog` evidence must be present. A legal disabled Hard row need not be active. This proves host/plugin/API readiness, not that an external provider executed a model request. |
| Undo evidence log | `files/undo-gate.log`, `.1` | `UndoGate` → device verification/diagnostics | Bounded observable evidence; not the source of target identity or health. |
| Safe Mode state | Default web: `files/home/.dsh/undo-snapshots/auto/safe-mode.json`; legacy scoped web state remains under `undo-snapshots/web/auto/` when it is the sole marker. Backups live beside the selected marker and content-addressed copies in its sibling `safe-mode-recovery/`. | Kotlin `SafeMode`, emergency CLI, vendored undo core → startup/Safe Console | Safe Mode's web resolver is local to this feature; generic snapshot roots and explicit custom/non-web stores keep their existing rules. A sole existing scoped marker remains authoritative; any marker in both flat and scoped locations, including malformed markers, fails closed. New state records profile identity. Before exit, all profile/home/package backup bytes are read and validated in memory; legacy vendor markers infer home restoration from a nonempty `homeBackup`. Each primary can fall back to the bound SHA-256 recovery object outside prunable `auto/`; failure of any required source refuses exit before changing any live file. Legacy digest-less backups remain primary-only. Backup paths, snapshot id, profile and digest are validated before write; verified in-memory bytes avoid a verify/reopen race. Ownership requires exact `{id,name}` membership in the fingerprint-bound Hard manifest. Safe Mode also filters rc2 profile `dsh.profile.bundles`, whose patches compose ahead of the profile patch: only exact factory `{name,version,patchSha256}` tuples from that same authoritative manifest survive. `patchSha256` is SHA-256 over `DSHBNDL1` plus each declared relative path and exact patch bytes with uint32/uint64 big-endian length framing, in declaration order. If active bundle identities are absent or bundle metadata/patch bytes cannot be verified, ON refuses before writing live files. The full original `package.json` is backed up to primary plus SHA-addressed recovery copy and restored byte-for-byte on OFF. Missing/corrupt ownership manifest makes ON return an explicit not-started result without changing live files. Filtering touches only third-party insert children and non-factory bundle selections; top-level config/disabled rows stay unchanged. Automatic quarantine likewise appends a Cordis disabled override while retaining the original insert and all user config. Never a disposable cache. |
| Factory profile repair | `files/.profile-patch-repair-<versionName>` | `EngineManager.repairProfilePatch()` → next startup gate; `LogCollector` reads for diagnostics | Per-version completion marker for APK #214 retired `disabled: true` migration. | Legacy DSH backup | `files/home/.dsh-backup` | Pre-0.13.2 interrupted refresh restore → `SnapshotUserData.restoreLegacyBackup()` | One-time additive recovery source for legacy upgrades; current snapshot transaction does not create it. Keep recovery support while old backups can exist. |
| Snapshot residue | `files/.snapshot-stage`, `files/.snapshot-stage-orphan-<timestamp>`, `files/.snapshot-previous` | `SnapshotTransaction` → startup recovery and age-gated reclamation | May contain the only rollback source after interrupted swaps. Reclaim only after journal/state proves it is no longer authoritative. |

### Snapshot transaction interruption matrix

| Journal state at next startup | Recovery action | Data and retry consequence |
|---|---|---|
| `STAGED` | Delete the staged tree and previous tree, then clear the journal. | The swap had not started; the live runtime and HOME remain in place. A later start can retry refresh. |
| `SWAPPING` | Roll back journaled/discovered displaced entries in reverse order after validating the previous tree. | On complete rollback, clear the journal and retry refresh on a later start. If any entry cannot be restored, retain the journal and previous tree, report the failed entries, and retry recovery at a later start. |
| `SWAPPED` | Treat this phase as the commit signal: write the journal fingerprint, then remove previous/stage trees and clear the journal. | Keep the activated snapshot and roll forward; do not restore the previous tree. |
| No journal | If the snapshot is fresh, reclaim transaction residue; otherwise remove only the stage tree. | A markerless previous tree may still be the only rollback source for an incomplete swap, so it is reclaimed only after freshness proves the live snapshot is activated. |

Before a journal is written, extraction happens in `.snapshot-stage` and does not change the live runtime. Extraction failure or staged-runtime validation failure discards the stage and returns without swapping the live runtime. A stale stage is discarded on refresh; if it cannot be deleted, startup may move it to `.snapshot-stage-orphan-<timestamp>` and continue. If that move also fails, refresh stops and retains the residue for diagnosis.

Automatic `UndoGate` restores only an explicit shell-recorded `known-good` ID for the current fingerprint. The emergency CLI's `restore-last-good` remains a separate manual command; the plugin Undo UI uses its API and explicit snapshot ID. Keep these separate from automatic rollback: `restore-last-good` is unsafe as an automatic fallback because plugin boot-state can advance without the whole engine becoming healthy.

### User recovery when automatic rollback has no trusted target

No current-fingerprint `known-good` target is an intentional stop, not a recovery claim. The automatic path must not substitute the plugin-authored `restore-last-good` pointer. The Error guide exposes Safe Mode startup as its primary action (it also writes the repair prompt to the clipboard) and may additionally run one bounded runtime-tree recovery when the previous refusal was a confirmed incomplete live runtime (`GuidePageRenderer.kt:503-515`); no number of guide actions is promised, and the guide never tells the user any command. The manual paths below (`node "$DSH_FILES_DIR/undo-emergency.mjs" list` / `restore <id>`) are reachable through the built-in Console only — they are neither printed on the guide nor auto-run:

1. If the engine identifies exactly one failed non-hard plugin, `UndoGate` removes only that plugin entry before checking for a whole-snapshot target. A missing/pruned/cross-install known-good pointer does not block this surgical path. Hard-manifest plugins are never pulled automatically.
2. The Error guide's primary **Safe Mode startup** action requires the exact Hard ownership manifest, creates a verified backup, removes third-party insert entries, preserves shipped plugins and retries startup. If the manifest is missing/corrupt, it reports that Safe Mode did not start and leaves the patch unchanged. From the built-in Console, `dsh safe status`, `dsh safe`, and `dsh safe off` inspect, enter, and restore that exact pre-Safe-Mode patch. Safe Mode is useful for third-party plugin failures; it does not disable a broken shipped plugin.
3. For an intentional whole-Soft/config restore, open the built-in Console (available from the guide, and also when the engine is down) and inspect available IDs with `node "$DSH_FILES_DIR/undo-emergency.mjs" list`. The shell exports `DSH_FILES_DIR`, and the app deploys this CLI into that directory before the engine start attempt. After choosing a listed ID, restore only that exact ID with `node "$DSH_FILES_DIR/undo-emergency.mjs" restore <id>`; do not use `restore-last-good` or `latest` as an automatic substitute. This explicit action may replace plugin/config state from the chosen snapshot; sessions, workspaces, attachments, and credentials are outside its restore set. It requires the embedded bash/Node runtime to be usable.
4. If the runtime tree itself is incomplete, the guide's existing snapshot-repair path rebuilds Hard from the bundled snapshot while preserving DSH_HOME user data. A missing bash/Node runtime cannot run the emergency CLI; the guide's Safe Mode action and snapshot repair do not depend on the CLI.

If Safe Mode cannot restore startup, no uniquely attributable Soft plugin can be removed, and the runtime is incomplete or broken, the app may still require a corrected APK/runtime update. Do not claim the automatic known-good path covers these cases.

## SharedPreferences

All listed preferences use app-private SharedPreferences storage. They survive APK upgrade and are outside snapshot restore. Keys below are current source constants or direct literals; dynamic key families are shown as patterns. The owner column names the source class responsible for reading/writing the keys.

| File | Keys | Owner / call sites | Meaning / sensitivity |
|---|---|---|
| `engine_lifecycle` | `user_shutdown` (Boolean) | `EngineService`: persist/read explicit shutdown state. | User explicitly stopped engine; BootReceiver/service respects it. |
| `dsh_engine_auth` | `cookie` (String) | `EngineAuth`: load, store, and remove engine auth cookie. | Engine auth cookie; secret. |
| `dsh-adb` | `a11yEnabled` (Boolean), `controlToken` (String, secret), `controlHeartbeat` (Long) | `DeviceControlService`: accessibility state, bridge token provision/status, and heartbeat. | Accessibility/control state and bridge auth. |
| `dsh-notify` | `channelsInitialized` (Boolean), `channel.<category>` (String; category is `silent`, `todo`, `report`, `question`, or `approval`), `cat.<category>` (Boolean; same category set), `suppressForeground` (Boolean), `suppressForegroundSchema` (Int), `suppressForegroundLegacy` (Boolean) | `NotifyCenter`: channel/category settings and foreground-suppression migration. | Notification channel selection/category switches, schema migration, and foreground preference. |
| `dsh-notify` | `notify.markerOffset` (Long) | `WatchdogV2`: notification event-stream cursor read/update through `NotifyCenter.prefs()`. | Durable event-stream cursor. |
| `dsh-notify` | `notify.deferred.v1` (String, versioned JSON) | `NotifySuppressQueue`: synchronous commit before source offset advances; `NotifyStore.start` restores and resumes delivery. | Pending notification content is app-private, bounded by 8 entries/5-minute TTL; settlement holds up to 32 content hashes for 5 minutes. Do not copy raw preference files into ordinary diagnostics or exports: several contain authentication secrets. No UndoGate durable state is stored in SharedPreferences; its recovery authority is the named app-private files above.
