# 壳侧四条文案的双语收口（#986 #987 #992 #1011）

四条 issue 同属「英文界面下露中文」，同一个 PR 逐条修。

## 现象与真因（逐条）

### #986 汇报栏首行仍是「已完成」

`reportLines` / `reportBodyRedundant` 里的 `entry.outcomeLabel.ifBlank { entry.outcomeLabel(app) }`
让**落库值永远优先**：`outcomeLabel` 是通知发出那一刻按当时语言写进条目的字符串
（`NotifyCenter.sendTest` 就是 `UiText.t(app, "已完成", "Completed")`），语言切换不重算。
注释写的是「按 outcome 重新算」，实现恰好相反。同一个模式在 `NotifyCenter.reportLine` 还有一份。

### #987 浮层目标行 / 相对时间回中文

`applyLanguage()` 的重算路径 `updatePickerRowText()` 里写死了 `"＋ 新会话"`——而面板构造时那一行
本来是 `t("＋ 新会话", "＋ New session")`，所以**切一次语言就回中文**，构造点的双语白写。
另一半更隐蔽：`relativeTime()` 全分支硬编码中文，而且值在**取会话列表时**就算死存进
`PickerSession.relative`，切语言后没有任何路径能重算。

### #992 通知降级提示

`degradedNoticeText` 的整句模板是内联中文，只有里面的类别名 `face.label(app)` 跟语言走。

### #1011 修复助手整页 + 三处

修复助手整页是内联中文字面量；另外三处是通知「回复」动作、免责声明对话框、插件页失败行的重试后缀。

## 修法

- **文案表落一处**：新增/收敛 `reportOutcomeHead`、`pickerTargetRowText`、`pickerRelativeTimeText`、
  `pickerSessionLabelText`、`NotifyCenter.degradedNoticeText`、`NotifyCenter.replyActionLabel`、
  `localDocDialogCopy`、`pluginLoadErrorMessage`、`RepairAssistantCopy`。
- **纯函数入口**：以上全部吃 `english: Boolean`，配套 `UiText.t(english, zh, en)` 重载。
  这不是为了测试而加的一层——`Context` 版本在 JVM 单测里拿不到英文分支（`isEnglish(null)` 恒 false），
  「英文态仍中文」这条缺陷因此在测试里**不可达**，正是它活下来的原因。
- **#987 的「切换后重算」**：`PickerSession` 改存 `updatedAt` 原始时间戳，行文案在**每次渲染**时求值；
  `applyLanguage()` 改调 `refreshPickerMarks()`（内含 `updatePickerRowText` + 选择器行重绘），
  不再只重算目标行。
- **数据不本地化**：会话标题、目录名、摘要正文、引擎给的 label 都是数据，中英文态都原样显示；
  判据只查**文案常量路径**。

## 负控（双向）

判据都在 `ShellI18nCopyTest`（12 → 15 条用例），断言的是生产代码用的那张表。

### 修前必红（已实测，摘要如下）

| 用例 | 修前失败摘要 |
|---|---|
| `reportHeadUsesTheCurrentLocaleNotTheStoredLabel` | 英文态首行 `已完成 · 修好了三处回执` |
| `pickerRelativeTimeFollowsTheLocale` | expected `unknown time` but was `未知时间` |
| `pickerTargetRowFollowsTheLocale` | expected `＋ New session` but was `＋ 新会话` |
| `pickerSessionRowsKeepDataButLocalizeCopy` | expected `Untitled session · 5 min ago` but was `… 5分钟前` |
| `applyLanguageRebuildsThePickerRows` | `applyLanguage()` 体内没有 `refreshPickerMarks()` |
| `degradedNoticeIsBilingual` | `系统已把「Questions」通知降级为静默——到系统设置里可恢复` |
| `notifyReplyActionLabelIsBilingual` | 回复按钮英文态 `回复` |
| `disclaimerDialogCopyIsBilingual` | 标题英文态 `免责声明` |
| `pluginLoadErrorMessageIsBilingual` | `Could not read plugins right now.　点击重试` |
| `repairAssistantControlsReadTheCopyTable` | 控件未读 `copy.send` 等表字段 |

### 反向判据（防「删掉就绿」）

- 中文那一份必须**非空且含具体中文**：`chineseCopyNeverDegradesToEnglish`、
  `repairAssistantChineseCopyStaysChinese`；中英不得是同一句（`assertNotEquals`）。
- 实测反向负控（临时把中文那份改成英文 / 改成空串）：

| 注入的缺陷 | 变红的用例 |
|---|---|
| `thinking = UiText.t(english, "Thinking", "Thinking")` | `repairAssistantChineseCopyStaysChinese`（`中文态必须含中文（实际：Thinking）`）与 `repairAssistantCopyIsBilingual`（`中英必须是两份文案`） |
| `degradedNoticeText` 中文分支改成 `""` | `degradedNoticeIsBilingual`（`中文态不得为空`） |
| `localDocDialogCopy` 中文标题改成 `""` | `disclaimerDialogCopyIsBilingual`（`expected:<[免责声明]> but was:<[]>`） |
| `pickerTargetRowText` 中文那份改成英文 | `pickerTargetRowFollowsTheLocale`（`expected:<＋ [新会话]> but was:<＋ [New session]>`） |

- 数据不得被本地化改写：`sessionDataIsNotRewrittenByLocalization` 断言英文态仍原样显示中文会话名，
  但「名字 · 时间」里时间那一半不得含中文。

## 自查抓到的一处接线缺陷（值得记）

第一版只改了 `OverlayReport` 的 head，测试全绿——但 `NotifyCenter.reportLine` 里还有一份同样的
`entry.outcomeLabel.ifBlank { entry.outcomeLabel(app) }`，也就是**通知本身**的首行仍会用落库中文。
issue 只点了汇报栏，同族那一份靠 grep 才发现。判据必须覆盖「同一个文案的所有渲染面」，
只钉 issue 点到的那一处会留下同形的第二处。

## 文档面

`OverlayPanel.kt` / `OverlayReport.kt` 的改动让 `docs/AGENTS/EXECUTION-MAP.md` 里的行号坐标整体漂移
（22 条锚点）。处理方式：按 `git diff -U0` 算出逐行位移，**先验证每个新坐标的内容仍与基线钉的
那一行逐字相同**，再同步改文档坐标与 `scripts/check-code-map-anchor-baseline.json` 的键。
锚点总数 1091 不变、耦合边 152 不变——不是靠删引用换绿。
