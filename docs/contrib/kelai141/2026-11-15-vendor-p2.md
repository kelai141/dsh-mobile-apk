## #1590 blob GC 与建快照无互斥（`vendor/dsh-undo-savepoint`）

- **真因**：`createSnapshot` 的顺序是 `mkdir` 占位 → 逐文件 `writeBlob` → **最后** `writeManifest`。
  中间那段「blob 已写、manifest 未写」的窗口里，该快照对 `listSnapshots` 不可见，
  它的 blob 在 refs 里一个都没有 ⇒ 并行来的 `undo_prune` / `undo_compact` 把它们当孤儿删掉。
  之后 `applySnapshot` 只能报 `snapshot blob missing` 跳过——安全网**静默**失效。
- **修法**：四层，缺一层都不算修好。
  1. `createSnapshot` 整段持有模块级 store-busy 计数（按 blob 库路径分组，不是挂在 `cfg` 上：
     局内 `index.js` 与局外 `tools/undo-server.mjs` 各自建 `cfg`，但共用同一个 blob 库）。
  2. 三条 GC 路径（`pruneAuto` / `pruneOrphanBlobs` / `undoCompact`）在 busy 或
     `cfg.undoBusy` 为真时整体让路，并**如实回传** `blobsSkippedBusy`——不能静默什么都不做。
  3. mtime 安全窗 `ORPHAN_GRACE_MS`（10 分钟）：进程内计数只能挡同进程并发，
     跨进程写者本进程看不见，所以最近写入的 blob 与 `.tmp` 一律跳过。
  4. `undo_prune` / `undo_compact` 的 `isConcurrencySafe` 从恒 `true` 改成 `() => !cfg.undoBusy`，
     `execute` 首行按 `undoBusy` 直接返回忙碌文案——声明与事实对齐。
- **判据**：`vendor/dsh-undo-savepoint/test/undo-gc-busy-1590.test.mjs`（5 例）。核心那条用例
  `fs.promises.readFile` 打桩，让 `createSnapshot` 停在「已写至少一个 blob、manifest 还没落」的窗口里，
  跑真实的 `pruneAuto`，再放行，检查 manifest 引用的每个 blob 仍在盘上且 sha1 相符。
  修前红：把 `core.mjs` 回退到 HEAD 字节，实测 4 例红（1 例是清理）。
- **为什么不用 cfg 上的单飞标志就够**：`restore` 的 `cfg.undoBusy` 只覆盖「撤销在飞」，
  而本条的另一半是「`undo_snapshot` 与 `undo_prune` 同轮并行」——那条路径上没有任何单飞标志。

## #1589 Claude Code 导入账号第一次刷新后脱离同步（`vendor/dsh-plugin-subscriptions`）

- **真因**：`keychainBound` 是「该账号跟随 `~/.claude/.credentials.json`」的唯一标记，导入时写入；
  但 `claudeSession()` / `refreshClaude()` 的返回不携带它，`refreshClaudeSynced` 返回的
  `base` / `next` 也不携带，而 `TokenManager.doRefresh` **每次都 save** ⇒ 第一次成功刷新就
  把标记从盘上抹掉，5 分钟同步定时器（`if (session.keychainBound !== true) continue`）从此跳过
  该账号 ⇒ DSH 不再读 CLI 轮换后的 token ⇒ 自己那份 refresh token 过期 ⇒ `invalid_grant` ⇒
  判永久失效 ⇒ 删会话。用户必须重新导入，且掉登录时没有任何提示说明原因。
- **修法**：`refreshClaudeSynced` 的两条出口（采用源里更新的 token / 自己刷新）返回前都过
  `keepBound()`：**只在入参本身带 `keychainBound: true`** 时才补。不做无条件透传——
  那会把普通 OAuth 账号也标成跟随 CLI 的账号。源模块 `lib/auth/claude-code-creds.js` 与
  打包产物 `lib/index.js`（`TokenManager` 内联副本所在的那份）**同步改**：#1588 的教训是
  只改源模块会让运行期加载的那份仍是旧行为。
- **判据**：`vendor/dsh-plugin-subscriptions/test/claude-keychain-bound-1589.test.mjs`（4 例）。
  第 3 例走**真实 `TokenManager.session()`**，断言落盘那一条仍带标记；第 4 例是反向保护
  （普通账号不得被打上标记）。修前红：两份文件回退后实测 3 例红、第 4 例绿（正是设计意图）。

## 坑位（值得记下来的那条）

**`vendor/dsh-undo-savepoint/lib/core.mjs` 与 `lib/index.js` 是混合行尾且被 `.gitattributes` 钉成 `-text`。**
`core.mjs` 里 2878 行 CRLF、434 行 LF（`index.js` 1186 CRLF / 43 LF）——这是上游产物 + 补丁反复施加的结果。
用编辑器的「整体替换」或任何会把换行归一化的工具改它，会得到 **978 行的伪 diff**（内容基本没变），
而 `scripts/check-upstream-patch-bytes.test.mjs` 的「canonical newline bytes」判据与
`scripts/patches/apply-patches.mjs` 的字节级锚点都以**原字节**为前提。
本轮做法：用脚本读 `utf8` 字符串、按**跨行锚点**做精确替换、新插入的片段用 `\r\n` 拼接
（原有 LF 段落原样不动），改完立刻 `node --check` + `git diff --numstat` 核对行数
（103 增 / 8 删，全部落在预期锚点附近）。**不要**用 `git checkout` 之外的任何方式「重置」这两个文件。
