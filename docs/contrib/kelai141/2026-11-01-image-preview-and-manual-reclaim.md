# 模型图片预览与手动回收

日期：2026-11-01 至 2026-11-02。本轮源码实现与验证记录；未发布，未更新用户手机安装包。

## 用户最终口径

- 发给服务商的是等比预览与压缩编码，不能原字节透传高分辨率截图。本地附件不因请求编码被覆盖。
- 预览最长边1600，路由设置更小的像素或字节预算时继续遵守。编码目标不超过1MiB，沿用现有85/75/60质量梯度；这是编码目标，耗尽候选后选最小版本的上游规则仍在，不能称为硬字节保证。
- 标尺、OCR与最终点击继续使用原屏幕坐标。当前工作树没有完整phone-vision功能；该分支的原图/OCR/标尺协同和缩小标尺可读性仍需集成验证，不能把请求侧变更当成视觉定位已验收。
- **120分钟是手动可清理门槛。没有自动到期、自动失效或定时删除。** 不点设置中的清理按钮，超过120分钟的图片仍能调用。
- 主动保存/读取图片会刷新时间；每轮请求被动重发历史图不刷新。文件内容寻址，相同图片被重新保存也会刷新同一对象的时间。
- 手动清理后，模型请求将缺失图片换成稳定占位文字，保留会话文字及当前可用图片。图片文件无法恢复；需要当前画面时重新截图。
- 清理包括符合条件的图片对象、请求预览、已知截图/标注临时文件与残留原帧。文件附件、会话日志、凭据、设置、插件和当前引擎日志保留。

## 改动及依据

上游只读基线：Harness `1f81c047fc48fa190a683e469daa699857e9afe8` / `0.2.1-rc.3`。

1. `scripts/patches/image-request-preview-P1.mjs`：固定版本预检attachment-local、llm-pi-ai、llm-deepseek三个真实包。两个请求目标解析器都约束1600长边，附件编码器取消原字节透传。变换版本更新，旧透传缓存不会被当成新预览；相同策略的历史请求继续使用确定的缓存字节。
2. `scripts/patches/image-expiry-E1.mjs`：主动保存/读取更新图片对象mtime，请求版本生成直接读取对象而不续期。预览缓存继承原图最后主动读取时间，避免旧图重编码后又多占120分钟。两种请求协议只把 `ATTACHMENT_NOT_FOUND` 转为占位；损坏、权限、解码等其他错误继续失败。原会话事件不被改写。
3. `plugins/dsh-android-linux-env/src/image-cache.ts`：只列举已知目录和名称的叶文件，不递归删除附件目录。120分钟之内、临时写入文件、未知文件、符号链接与越界路径不进入清理。扫描与执行分别复核时间和范围；主动读取后即使曾被扫描，执行时也应跳过。
4. `runtime-cache.ts`、`index.ts`：复用原GET扫描、POST执行、鉴权、确认及审计。只有附件运行时报告支持占位回退，才允许清理原图片对象；旧运行时保留对象。**没有增加定时器或模型可见清理工具。**
5. `dsh-client-ui-responsive/src/client/dev-section/runtime-cache.tsx`：中文、英文说明和确认文案明确手动120分钟门槛及删除图片的后果。

图片对象目录的依据：`attachment-local/src/store.ts` 的 `normalizedImagePath` 指向 `attachments/v1/objects/<前两位>/<sha256>`；文件附件使用其他命名空间。请求缓存依据：`request-image.ts` 的 `request-images/<前两位>/<variant hash>`。这些位置来自实际代码，不按目录名猜测可删性。

## 集成问题与修复

热推产品运行时后，确认原生启动会用旧附件资产覆盖新模块；清理兼容守卫正确阻止了原图删除。修复为从固定版本完整补丁快照提取同源附件资产，并实际重新打包。最终快照与启动资产逐字节对账通过，安装后及冷启动后的实际模块哈希也都匹配。资产登记见 `docs/AGENTS/RUNTIME-PATCHES.md` §2，产物与设备明细见同目录 `2026-11-01-image-cache-device-evidence.json`。

旧底座缺少当前清单要求的9个遥测嵌套依赖、共享undici链接、自定位npm/pnpm入口，以及最新裁剪项。已在独立临时树补齐现有构建规则：依赖逐包校验官方npm SHA-512，命令入口复用canonical生成器，浏览器文件使用现有降级器，并执行当前slim清单。移除的证书模板和Coveralls配置来自公开第三方包，不是测试写入的用户凭据。没有为这些材料放宽敏感内容检查。修复前失败的构建不计通过；最终完整Fast链退出0，Kotlin单测2230项、486项包版本断言、156个浏览器文件检查通过，敏感内容和资产检查SKIP=0。

未修改的几何配套曾被误要求带P1注入标记，现按真实函数签名登记；三个改动模块仍要求P1标记。登记改变后从真实固定版本产物重新捕获63个夹具文件，内容未变，仅捕获的登记表摘要更新。新增回归用例防止误要求复发，没有手改夹具字节或刷新门禁基线。

资产门禁原来只物化主文件，不足以执行P1/E1多文件正文检查。APK canonical门禁现从同一快照提取在册配套文件与包身份，候选主资产保持独立，不能被快照文件替换。新增真实CLI正控、缺配套/配套正文漂移负控、主资产正文漂移负控；自检11项通过，完整快照3组资产校验SKIP=0。没有放宽正文、marker或同字节要求。

## 同源调试包的设备验收

完整Fast链产物为本地x86_64测试包。随后用同一份快照与附件资产生成debug包，供CDP检查；两个APK的对应资产哈希逐项核对。设备是独立Android 15/API 35模拟器，主ABI为x86_64、240dpi，Node 24.18.0。Fast包本身未安装；本轮实际设备验收覆盖同源debug包，不能当作发布候选验收。

- 英文横屏1600×900：从真实设置页进入开发者选项，扫描、打开确认、取消均不删图；确认后仅旧图片对象和预览被清理。新图、主动重新读取过的图、文件附件及存在的配置保持原字节，当前日志前缀不变。
- 中文竖屏900×1600：重新准备样本，实际点击确认清理旧图片对。文案说明120分钟仅为手动门槛；列表无横向溢出，按钮可命中，结果与磁盘检查一致。
- 临时文件补测：普通原图、标注图、浏览器截图、残留原帧四类旧文件均被实际按钮清理；近期同类文件和未知名称文件保留，附件与配置哈希不变。测试保留项随后由测试脚本按记录清收。
- 冷启动：快照指纹与附件模块哈希仍匹配候选，P1/E1未被覆盖；可用图片及预览字节保持稳定。
- 历史回退：使用实际SDK构造混合历史，调用设备上真实Pi和DeepSeek函数的临时导出副本；旧图为占位、当前图保留，原历史对象不改写。探针结束后删除导出副本，并确认生产入口字节未变。**没有发起服务商请求**，不把此项称为真实模型会话验收。

**时间条件为受控测试**：只把自建样本的mtime设为121分钟前，系统时钟不变；不是实际连续等待两小时。主动读取续期走真实附件服务，普通扫描及历史重发不续期。界面由主线程Agent根据观察自行编排ADB操作，CDP只读取状态和扫描结果，清理通过真实按钮触发。

证据在 `.deploy-tmp/image-build/` 和 `.deploy-tmp/image-live-qa/`：`fast-chain-fully-prepared.log`、`apk-artifacts.json`、`en-scan/en-cancel/en-cleared.json`、`zh-scan/zh-cleared.json`、`temp-scan/temp-cleared.json`、`history-{english,chinese,restart}.json`、`runtime-{boot,restart,final}.json`，以及对应 `ui-*.png`。无本机标识的摘要随本文入库。验收后已按记录校验并清收自建测试图片及工作目录，保留原有用户设置；没有运行后台清理。

## 验证边界与回退

本分支图片缓存功能的代码、CDP和ADB验收已完成。尚未验证ARM64耗时、密集小字与游戏点击误差、完整phone-vision标尺在1600预览上的可读性，以及真实模型请求/服务商usage。编码字节减少不等同于视觉token实测；未发布，用户手机测试包未改动。

如需回退，成组移除清理对象授权与E1请求回退；不能保留对象删除却先退掉占位支持。P1预览可单独回退，但旧缓存版本与新版本不能混认。已手动删除的图片无法由代码回退恢复。
