# SafeMode 注释保留与迁移收敛（#582 的 M-7A / M-7B）

#582 混了三件事，#614/#615 只覆盖了截图管道与归一化备份两块。这两块是**唯一没被承接**的部分，
本 PR 单独收口，也是关闭 #582 的正当理由之一。

## M-7A：insert 组边界吞掉列 0 注释

`filterThirdPartyInserts` 的组终止判据是 `^-(?:\s|$)`——只认顶层列表项。insert 组后跟随的
**列 0 注释**因此被吞进组体；组内第三方条目被摘光时整组连同注释一起删掉，注释**静默消失**。
这与函数文档「其余内容逐字保留」直接矛盾。

真实 patch（`profile-web.cordis.patch.yml`）组间全是列 0 注释，而共享 fixture 恰好零列 0 注释——
缺陷因此活到第七轮审计。

修法：三处组扫描统一改 `endsInsertGroup`（任何列 0 非空行即终止）。子条目恒有缩进，列 0 内容
不可能属于组内，所以这个边界是精确的，不是放宽。

## M-7B：迁移崩溃窗口把用户锁死

`migrateLegacyState` 的写序是「原子写 current → 删 legacy」。在两步之间被打断会留下两份状态文件，
而它们**逐字节相同**（current 正是 legacy 的副本）。旧实现一律拒绝且不给出路，文案只写「拒绝猜测
恢复来源」——enter / exit / status 全部不可用，用户只能手改文件。

修法：内容一致即收敛为「删旧继续」；只有真正不一致（另一来源正在写）才保留拒绝，并在文案里补
处置指引。

## 证据

- `SafeModeInsertBoundaryTest` 7 例全绿：列 0 注释保留、整组被摘时注释不跟着消失、组内缩进注释
  仍属组体、无改动时逐字节不变、双状态文件相同即收敛、不一致仍拒绝且两份都留、拒绝文案给出路。
- 负控：还原 M-7A 的旧判据 + M-7B 的无条件拒绝，同一组用例 **7 例中 5 例判红**；恢复后 7 例全绿。
- 全量 `:app:testDebugUnitTest` 0 失败；`check-code-map` / `check-kotlin-comments` /
  `check-kotlin-test-count` 全过。
