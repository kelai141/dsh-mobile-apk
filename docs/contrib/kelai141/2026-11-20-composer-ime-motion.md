# 主会话输入区跟随软键盘开合

键盘展开和收起时，欢迎区输入框有明显的停顿和速度变化。已有会话的输入区也会在切换键盘状态时跳一下。

主 WebView 已经随 IME 逐帧缩放。欢迎区又用 IME 高度撑开顶部留白，先抵消视口的位移，留白用尽后才移动输入框。已有会话的导航栏预留由布尔状态一次性切换。原生进度回调还会重复查询窗口尺寸。

欢迎区的上下留白现在相等，随当前视口连续变化。已有会话只保留 IME 尚未覆盖的导航栏留白。原生在窗口边界或 insets 变化时刷新窗口尺寸，逐帧复用该尺寸，并跳过重复的 CSS 高度和样式写入。

浏览器夹具覆盖横竖屏的新会话与已有会话，每组取键盘开合 25 帧。旧样式共 49 帧偏离预期，修复后 100 帧均通过。前端 1,436 项测试与执行地图检查通过。

Kotlin 全量单测和用例数门禁通过。MuMu 上覆盖安装同源码的 x86_64 测试包，等待快照指纹更新后，以 Gboard 验证横竖屏的输入、返回键收起和位置复原。采样期间输入框的移动方向一致。关闭 CDP 采样后录屏仍能看到 WebView 画面更新滞后，模拟器结果不足以确认流畅度。ARM64 APK 的签名、原生库、内嵌 Node 架构和前端文件均已校验，真机流畅度待复测。
