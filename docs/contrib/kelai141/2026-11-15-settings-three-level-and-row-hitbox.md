# 设置中心三级页与整行命中面（2026-11-15）

用户真机实报三条，落在同一屏「设置 → 手机控制」上：

- A：一屏出现**两个返回按钮**（上面那个退到设置首页，下面那个退到「手机控制」）。
- B：进到第三层（无障碍通道 / Shizuku 授权）后按系统返回，**直接跳回设置首页**，第二层被跳过。
- C：列表每行**右侧（状态文案 + 箭头）点不动**，只有左侧文字能点。

## 共同真因：同一个模型缺口，三条各自是它的一个面

设置中心的竖屏分层容器 mobile/settings-nav.ts 的层级模型是**两级**：home 与 detail。
而「手机控制」这个分区**自己还有一层下级页**（view: 'a11y' | 'shizuku' | …），这一层不在模型里：

- **B**：用户在第二层里点进下级页时，容器仍认为自己在 detail，于是系统返回（= 点蒙层）
  走 detail -> home 分支 ⇒ 一口气跳过「手机控制」这一层。
- **A**：因为容器不知道有第三层，它继续用自己的顶部条（含返回箭头）显示**第二层**的语义；
  而分区也在自己页眉里画了一个返回箭头 ⇒ 一屏两个箭头，且两者退的深度不同。
- **C** 与上述模型无关，是同一屏上的另一个独立缺陷（见下）。

## 修法

### B：让第三层进入模型，但不猜它

判据不从分区内部 state 猜，而是让分区**自己把「我在一层下级页」登记到 DOM 上**：

```
data-dsh-settings-sublayer        // 存在即表示本分区已下探一层
data-dsh-settings-sublayer-title  // 这一层的名字（容器拿它当顶部条标题）
data-dsh-settings-sublayer-back   // 分区自己的返回控件（容器点了它就弹本层）
```

容器读这三个事实：data-dsh-settings-depth 写 1，goBack 先走 popSublayer。
分区没登记 = 它就停在第二层，行为与改动前**完全一致**（零回归面）。

**深度为什么不复用 data-dsh-settings-level**：那张属性驱动整张样式表（列表 / 内容两套布局），
再加一个取值要把每条 detail 规则都改成 :is(detail, sub)，收益为零、回归面却是一整屏。
第三层是**二级页内部**再往下的一层，独立一个深度属性既准确又不动布局。

### A：只留一个返回出口

手机形态下隐藏分区页眉自己的返回箭头（html[data-dsh-mobile-form] … .dsh-pc-back 设 display:none），
顶部条那一个成为唯一出口，且它已被接管为「弹回本层」。横屏（无 data-dsh-mobile-form）不装配
分层容器，分区页眉的箭头仍是唯一出口，故不隐藏——同一条规则在两个形态下都各留一个。
页眉里的重复标题（顶部条已显示同一句）改成只留语义、不留视觉，读屏仍读得到。

### C：可点面从来没覆盖整行，不是被谁挡住

缺陷形态：一行是 div.dsh-pc-row > button.dsh-pc-row-main（左侧标题+说明）+ span.dsh-pc-side（纯展示）。
**可点区域就是那个 button 的盒子**，右半截从来不在命中面上。它不是被遮挡、不是 pointer-events 被吃掉、
也没有 stopPropagation——div 上没有事件，span 也不是控件。所以「给右侧补一个 click」是错的修法：
那样同一行会有两个命中面、中间仍有一段点不动，而且一个语义变成两个焦点。

修法：**整行收敛成一个 button**，左侧文字退化成 span.dsh-pc-row-main，右侧状态/箭头仍是它的子节点。
可点面 = 整行，一次语义、一个焦点。行内原先可嵌的次级按钮（inlineLabel/onInline）随之一并删除：
按钮不能嵌套按钮，而该能力在本文件里**从未有过调用点**。


### B 的真机返工（第一次修法为什么没成）
第一次修法的契约是「容器去点分区登记的返回控件」。单元层全绿，真机却没退——因为
手机形态下那个控件**正是被样式表藏掉的那个**（一屏只能有一个返回箭头），而全局激活护栏会拦掉
落在隐藏控件上的程序化点击。于是返回被派发到页面栈后，什么都没发生（设备实测：仍停在第三层，
`dsh-back` 日志已显示 `DISPATCH_PAGE_STACK`）。

结论：壳侧不该靠伪造点击去操作一个自己藏起来的控件。契约改成**可取消事件**——
容器在分区登记的节点上派发 `dsh-settings-sublayer-pop`，分区监听、`preventDefault()` 并自己退；
控件点击降为兜底（分区只登记控件而没监听事件时仍能退一层）。
判据随之下沉为「控件被隐藏时返回键仍必须退一层」，并带一条负控：该控件若被点即抛错。
