# 瞬态不能当稳态；重叠判定必须用区间相交

2026-10-31 排查 apk #783（底部留白 + 悬浮按钮遮挡）时连续误判两次，两次都把一个**看起来像结论**的读数直接写进了报告。记录下来，因为这两类错都很容易在别的排查里重犯。

## 一、observer 首帧前的瞬态被当成稳态

**现象**：CDP 读到 `getComputedStyle(scroller).getPropertyValue('--dsh-composer-height')` 为空，据此断定「该变量从未被设置，恒用 152px 回退值」，并把它当成「按钮被顶进正文」的根因写进了结论。

**真因**：该变量由上游 `ui-conversation/.../ConversationContent.tsx:53-67` 的 `ResizeObserver` 异步写入。页面刚挂载、observer 尚未跑第一拍时，变量确实不存在——但这只是**首帧前的瞬态**，不是这个系统的稳态。把 `page.reload` 之后立刻取的读数当成了常态。

**修法（也是判据）**：凡「某变量/属性从未被设置」「某元素不存在」这类否定式断言，必须**在稳定帧之后取两次，两次一致才算**。具体做法：

    // 第一次采样
    let a = read()
    await new Promise(r => setTimeout(r, 800))
    // 第二次采样，与第一次一致才作为结论
    let b = read()
    if (JSON.stringify(a) !== JSON.stringify(b)) { /* 仍在收敛，继续等 */ }

同一轮里还可以做**主动扰动**来自证稳态：把被观察元素人为撑高（本例给 seat 加 60px padding-top），若变量随之更新，即可确认 observer 在工作，而不是变量根本没接线。

**复验证据**：稳态下实测 `scroller.style['--dsh-composer-height'] = 128px`、`seat.offsetHeight = 128`；横竖屏切换后仍同步；人为把 seat 撑到 188px 时变量随之更新。结论从「变量未设置」翻转为「变量设置正确」。

## 二、重叠判定用「末边相减」，公式本身就是错的

**现象**：报告「按钮压住正文 44px」，并据此判断存在严重遮挡。

**真因**：算式写成 `btn.bottom - lastText.top`。这个差值既不是相交高度，也不是任何有意义的距离——它把按钮的全部高度和文本的位置混在一起减，只要按钮在文本下方一丁点，结果就会是个正数，看起来像「大面积遮挡」。

**修法**：矩形重叠只有一种判据——**区间相交取交集**，两个轴都要算：

    const overlapX = Math.min(a.right, b.right) - Math.max(a.left, b.left)
    const overlapY = Math.min(a.bottom, b.bottom) - Math.max(a.top, b.top)
    const overlaps = overlapX > 0 && overlapY > 0   // 任一轴 <= 0 就是不相交

**复验证据**：改用区间相交后，滚到底的真实几何是：

| 视口 | 按钮包围盒 | 最后一行文本底 | 间隙 | 是否相交 |
|---|---|---|---|---|
| 600x1067 竖屏 | 889-923 | 879 | 10px | **否** |
| 360x796（复刻报告人） | 618-652 | 608 | 10px | **否** |

即：**滚到底时按钮根本不压内容**。遮挡只发生在滚动途经时（扫点实测：距底 320px / 400px 时整高 34px 压在正文上，距底 80px 时压 16px，其余采样点 0）。

## 三、附带教训：验证性实验要先做「能证伪」的那一档

在决定「给滚动区加 padding-bottom 补偿」之前，先做了实现与单测（1038 例全绿），推到设备才发现无效。**正确的顺序是先做一次极端的活体实验**：把 padding 直接设成 0 / 58 / 200px 三档，观察相交数是否变化。实测三档相交数恒为 1 —— 说明方向本身错了，因为浮层 `height: 0` 不参与布局，padding 只拉长尾部空白。

一个 5 分钟的活体实验，能省掉一个含测试、含注释、看起来完备但方向错误的实现。**先证伪方向，再写实现。**
