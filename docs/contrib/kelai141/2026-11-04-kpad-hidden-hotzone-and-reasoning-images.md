# 红米 K Pad 的三条 UI：透明盒仍可点、非输入控件抢键盘、reasoning 图片不可放大

日期：2026-11-04 · 面：`dsh-client-ui-responsive`（客户端适配层，`src/client/**`）· 设备：红米 K Pad（HyperOS 3.0.310.0 / Android 16 / 3008×1880，由 issue 报告方提供）

## 现象

1. **#1317**：会话卡片上的「更多 / 归档 / 置顶」在**不显示**的状态下，点对应位置仍会触发；抽屉里「开启新对话」同样有看不见的热区。用户以为点在空白处，实际归档/置顶了会话。
2. **#1316**：在工作区文件夹或对话标签里点「暂停对话」，软键盘被弹出来。
3. **#1319**：思考过程（reasoning）里渲染的图片点不开预览；正文里的图片可以。

## 真因

- **透明不等于不可点**：上游用 opacity/visibility 这类「只影响绘制」的方式隐藏控件，**透明盒仍然参与命中测试**。所以命中区与可见性在这类隐藏方式下天然不一致——只调 opacity 永远修不掉「看不见却点得到」。
- **焦点是键盘的唯一开关**：软键盘由「可编辑元素拿到焦点」拉起。非输入控件被点后若上游把焦点塞回输入框，键盘必然弹起；这一点与按钮自己的视觉无关。
- **reasoning 走的是另一条渲染路径**：`ui-chat` 里正文图片与 reasoning 正文分属两个 Slot（`conversation.chat.message.images` 对 `conversation.chat.reasoning.body`），预览入口由填 Slot 的渲染器提供；本仓适配层**没有**任何「打开预览」的代码，所以这条不在本仓可修范围。

## 修法

新增 `src/client/mobile/activation-guard.ts`（一个 attach/detach 对，两条同源不变量）：

- **隐藏控件不得激活**（#1317）：捕获期吞掉 `pointerdown`/`click`，并把控件同时移出命中面（`pointer-events:none`）、聚焦树（`tabindex=-1`）与无障碍树（`aria-hidden`）；重新呈现时逐条还原，`detach()` 也全部还原。判隐藏用 DOM 事实（`hidden` / `aria-hidden` / `display` / `visibility` / **祖先链累积 opacity**），因此不绑上游某一版 CSS 写法。
- **非输入控件不得抢键盘**（#1316）：只对「按钮 + 不在输入卡片 / 侧栏 / 对话框 / 菜单内 + 非菜单开启者」的激活开 250ms 短窗；窗内可编辑元素拿到聚焦即 blur；**用户下一次按下立刻撤销**，点输入框永远优先；截止时刻是唯一真源，不挂定时器。

#1319 不修：结论与证据留在 PR 与 issue，建议走 `scripts/patches/**`（镜像面）或上游。

## 复验证据（代码层）

- `npx vitest run`：76 文件 / 1154 用例全绿，其中新增 `tests/activation-guard.spec.ts` 10 例（真 `pointerdown`/`click`/`focus` 事件、`document.activeElement`、事件是否被取消、属性是否写/还原）。
- 负控逐条实测变红：不吞激活、透明度不算隐藏、不打三处标记、用户按下不撤销窗口、不排除编辑器区域、窗口永不失效。
- **设备层：未做**（本机无 K Pad）。待验项写在 PR 正文；C 端症状是否消失必须由该机复核。

## 可复用的教训

1. 「隐藏」必须同时是视觉、命中、聚焦、无障碍四件事；只改 opacity 的那份隐藏一定会在触屏上变成误触。
2. 判据要按「计算样式 + 属性」而不是某一版上游 CSS 写法，否则上游换代时修法静默失效。
3. 修「焦点被抢」不要用全局 blur：按一次激活开一个**短窗**，并在用户下一次按下时撤销，才是可解释的行为。
