# #1042 + #1043 浮层面板「发送 -> 失败回填」链路：sessionId 写死空串 / 回填覆盖新输入

两条 issue 缠在同一段编排（`OverlayService.requestSend()`）里，一个 PR 修：**发送时现取 sessionId**、
**失败回填前先判用户动没动过**。修复同时把两处判定抽成 internal 顶层纯函数，JVM 单测直接调。

## 现象

- **#1042**：目标行停在「+ 新会话」时发送，wire 上先 `POST /api/session/create` 成功，
  随后的 `POST /api/session/prompt` 里 `args.request.sessionId` 却是空串。
  引擎拒绝时用户看到「发送失败」，而列表里多出一个空会话；引擎若把空串当「当前会话」，
  多会话并存时会落到别处。
- **#1043**：发送失败时输入框被整段回填。`postRpc` 的 `connectTimeout=3000` / `readTimeout=8000`，
  失败回包最晚 8 秒后才到——这 8 秒里用户敲的新内容被 `setText(text)` 覆盖掉。

## 真因（修前行号，基于 68faa52d）

- `OverlayService.kt:762-767`：payload 在**请求发起前**构建，`:764` 直接
  `.put("sessionId", activeSessionId)`；而「是否新会话」的判断在 `:782`。
  目标=新会话时 `activeSessionId` 此刻是空串，`:791` 才赋值，`:796` 的 `send.run()`
  用的仍是那个已经固化的 `val payload`。`postRpc`（`:698-721`）只把 payload 包进
  `{type:"client-request", method, payload:{args}}`，不会回填 sessionId。
- `OverlayService.kt:777 / 798 / 802`：三处失败分支无条件 `panel.inputBox?.setText(text)`，
  判据里根本没有「当前输入框内容」这一项。

## 修法

1. **payload 挪到发送时刻组装**（`requestSend` 内的 `send = Runnable { ... }`）：
   `sessionId` 用 `payloadSessionId(activeSessionId)` **现算**——create 成功后
   `activeSessionId` 已是新 id，此刻取值才正确。
2. **requestId 仍留在 Runnable 之外**：它是幂等键，一次用户发送只生成一次、create 与 prompt 复用。
   顺手把它挪进 Runnable 会变成「两次不同请求」，重试不再幂等——这条有专门的反向判据钉住。
3. **三处失败分支统一走 `restoreAfterFailure(text, reason)`**：先算 `failureBackfillPlan`，
   只在「用户没动过」时回填。
4. **原文可找回**：回填被拒时 `copyFailedSend` 把原文写进**剪贴板** + `LogCollector` 日志，
   状态行文案带上原文与去向（`...；<原文> 已复制到剪贴板 / copied to clipboard`）。
   选剪贴板的理由：`flashStatus` 有 `if (expanded)` 守卫且只闪 2.5s（坑 148），面板一收起就看不见；
   可见失败气泡要新增窗口与布局，属另一个 PR 的体量；剪贴板是唯一能跨「面板收起 / 服务重启」存活的载体，
   日志作为剪贴板被系统拒绝时的兜底。**只在拒绝回填这一支写剪贴板**——用户没动过时改剪贴板是没人要求的副作用。
5. **两处判定抽成 internal 顶层纯函数**（`payloadSessionId` / `failureBackfillPlan` + `BackfillPlan`），
   放在 `OverlayService.kt` 文件末尾的类外：Service 在 JVM 里实例化不了，判定必须离开类实例；
   不新增 .kt 文件，避免动 EXECUTION-MAP 的覆盖账本。

## 判据（`app/src/test/java/com/dsharnessmobile/shell/OverlaySendBackfillTest.kt`，11 例）

纯函数判据 + 源码级判据两层。**修前红**（源码级三例，3/3 红，失败点即缺陷本体）：

```

    java.lang.AssertionError: 旧形态仍在（payload 在 create 前就把 activeSessionId 写死）
```

修前那一版刻意只留源码级判据：纯函数判据要引用尚未存在的 `payloadSessionId` / `failureBackfillPlan`，
那只会得到「未解析引用」编译错误，证明不了缺陷。

## 负控（反向判据 / 变异测试）

修复落地后对实现做 6 个变异，逐个跑本测试类，**全部转红**：

| 变异 | 方向 | 转红的用例 |
|---|---|---|
| `payloadSessionId` 恒返回空串 | 过度修复 #1042（一律当新会话） | `payloadSessionIdTakesTheKnownSession` |
| 建会话分支条件改 `if (false)` | 删功能（新会话路径死掉） | `sendUsesSessionIdResolvedAtSendTime` |
| sessionId 回退成写死 `activeSessionId` | 回退 #1042 | `sendUsesSessionIdResolvedAtSendTime` |
| `untouched` 恒 false | 过度修复 #1043（永不回填） | `backfillStillRestoresWhenTheBoxStillHoldsTheSentText` / `...LeftTheBoxEmpty` / `backfillDecisionTreatsBlankInputAsUntouched` |
| 守卫内 `copyFailedSend` 换成 `Unit` | 假修复 #1043（不回填也不另存） | `backfillGuardLooksAtTheCurrentInputAndPublishesTheReason` |
| requestId 挪进 Runnable 现生成 | 过度修复 #1042（幂等键被破坏） | `requestIdIsFixedOncePerSendSoTheRetryIsIdempotent` |

前两个变异第一轮**存活**（M2 建会话分支、M5 丢弃原文）——当时的断言只查「`postRpc("session/create"` 在场」
与「`if (!plan.shouldRestore)` 在场」，而变异体把**条件改成恒假**、把**守卫体换成 Unit** 后这两段字面量仍在。
已补强为「入口判据必须是 `if (payloadSessionId(activeSessionId).isEmpty())`」与
「守卫内必须真的调 `copyFailedSend(plan.original)`」，第二轮 6/6 全红。
**这条是本轮最值得记的经验：断言「代码在场」挡不住「代码在场但不可达」，必须断言到达它的那个条件。**

## 遗留

- **未做设备验证**（本轮只跑 JVM 单测 + 静态门禁）：wire 上 `sessionId` 的实际取值需要引擎在线 + 面板操作，
  按 §4 铁律 2 需在进入发版候选前补三层验收。
- #1043 的「引擎在线但接口失败」状态机上机不易构造，本次以纯函数判据 + 源码级判据为准。
- 回填被拒时原文进剪贴板这一支**未在设备上验证**（`ClipboardManager` 在后台服务里写剪贴板受系统限制的情况未实测）。
