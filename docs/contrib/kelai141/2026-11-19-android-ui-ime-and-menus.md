# Android 输入区域和弹层回归

| 现象 | 源码原因 | 修改 |
| --- | --- | --- |
| 新会话欢迎区和输入区随键盘跳动 | `MainActivity` 先写 WebView padding，`ComposerImeOffset` 又移动输入卡，前端 `KeyboardBoundary` 还会按视觉视口改外框高度。新会话的欢迎区和输入卡因此按两套边界移动。 | `MainWebImeLayout` 按系统 IME 动画逐帧调整 WebView 实际尺寸。欢迎区保留居中布局，键盘接近时由弹性留白把输入卡留在可见范围内。 |
| 已有对话的输入区闪烁或被裁切 | 输入卡的 transform 脱离原停靠区的布局位置，同时外框按旧的视觉视口高度裁切。动画目标值和中间帧也可能先后覆盖尺寸。 | 移除卡片 transform 和外框高度钉定。原生动画期间采用进度帧，结束时同步终值。聊天滚动容器和输入区使用同一个布局视口。 |
| 工作区视图选项打开时侧栏收起 | 上游按钮没有弹层语义属性，捕获阶段的通用点击监听将它当作导航。旧 WebView 缺少 CSS anchor 定位，菜单默认落到视口边缘。 | `PanelNavDrawer` 排除工作区头部本地操作。旧 WebView 由 `HeaderPopups` 把菜单重新锚到触发按钮。 |
| 子智能体目录越出屏幕 | 上游目录靠 CSS anchor 和 `100dvh` 定位。旧内核忽略 anchor 规则，原有高度限制也没有扣除入口到可视边界的距离。 | `HeaderPopups` 读取触发器和 `visualViewport`，结合安全边距选择展开方向及高度上限。目录本体按内容收缩，列表内部滚动到末项。 |
| 原生悬浮输入区丢失键盘 | 展示已挂载的输入区也可能清掉编辑焦点。主动拉起 IME 可以早于窗口焦点。固定高度比较反复更新仍为 `WRAP_CONTENT` 的窗口，窗口外触点又按请求参数判定。 | `OverlayV2` 保留已挂载编辑器的焦点，由系统测量窗口内容并按实际屏幕坐标判断外部点击。无坐标的跨窗口事件交由焦点和返回键处理。`OverlayComposer` 等窗口获取焦点后才发起一次 IME 请求。 |

## 复验证据

- `npm run build` 和前端测试通过，共 1434 例。`testDebugUnitTest`、Kotlin 用例数门禁和执行地图门禁通过。Android 调试 APK 通过 `assembleDebug` 构建并覆盖安装。
- 在 MuMu 的 Android 15 和 WebView 110 上热推前端。ADB 点开工作区视图选项，再选中当前分组，侧栏始终展开。菜单上沿与触发器下沿相差 5 CSS px。
- 同一 WebView 用上游目录样式建立 50 行数据夹具。ADB 滑到滚动上限 1452 CSS px，末项完整可见并收到点击，页面滚动值为 0。
- MuMu 自带输入法报告显示时，键盘 Insets 高度为 0。切换到 Gboard 后，竖屏键盘打开时 WindowManager 的键盘上沿和 WebView 底边都在物理坐标 1094 px。CDP 读到布局与视觉视口均为 730 CSS px，`offsetTop` 为 0。已有对话的输入区持续可点，键盘收起后视口恢复到 1067 CSS px。
- 新会话竖屏的输入卡在键盘开合前后位置一致。横屏键盘打开后，视口缩到 309 CSS px，输入卡下沿也在 309 CSS px。收起后视口与卡片回到初始尺寸和位置。
- 横屏打开键盘时，50 行目录夹具的弹层下沿为 297 CSS px，距可视区下沿 12 px。内部滑到末项后能点击，页面滚动值仍为 0。
- 在启动器上长按 DSH 悬浮入口并打开输入区。点击 Gboard 屏幕按键后，`dsh-overlay-v2-composer` 仍是窗口焦点和 IME 输入目标。返回键只收键盘，切回 DSH 全屏后悬浮输入窗口退出，输入目标切到主 WebView。
- 厂商真机 IME 动画和系统自由小窗未做设备验证。
