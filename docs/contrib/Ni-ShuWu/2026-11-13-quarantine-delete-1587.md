# 永久删除必须覆盖隔离副本（#1587）

- 现象：隔离后再永久删除返回 404/not-found，客户端按幂等成功处理，但 `.corrupt/` 仍保留整份数据。
- 真因：删除只解析正常扫描路径；隔离查找只用于隔离接口，且枚举错误被吞为「没有副本」。启动 sweep 也只访问正常目录层的删除残留。
- 修法：删除前先解析正常目录和所有同 id 的隔离副本，再复用原有 rename、卸载失败回滚、最终 rm 的事务。任一删除失败不报成功；隔离区枚举异常与链接形态拒绝，不冒充不存在。重试与启动 sweep 均能清理隔离区的显式删除残留。
- 数据边界：不增加隔离 TTL。隔离承诺可恢复，只有用户明确永久删除才清除对应副本；不清理其它 id 的隔离件。
- 复验：`node plugins/dsh-session-delete/build.mjs` 后跑全部插件测试；新增真实临时目录、HTTP 路由、EACCES 受控失败、卸载回滚与旧逻辑负控。见 PR 中命令和实际结果。
- 验证边界：用户明确禁用 ADB 和模拟器；未做设备验证。无快照热推或 APK 安装，发布候选前需补齐设备证据。
