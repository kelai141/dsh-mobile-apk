# 回到底部按钮遮挡正文（#1145）

## 现象与真因

上游的回到底部按钮放在零高 sticky 容器内，位于正文右下角。增加底部 padding 只能改变尾部距离，
不能阻止滚动途经的文字从按钮下面经过。

## 修法

响应式插件在 `data-chat-flow` 列内部始终预留 52px 右侧区域，供 44px 按钮与 8px 间隔使用。
上游容器已有按正文最大宽度计算的右对齐，因此窄屏与宽屏都沿用同一几何关系。
按钮仍复用上游事件、语言标签与跟随尾部状态；不搬动 React 节点、不增加底部 padding。
预留在按钮卸载后仍保留，避免滚动到尾部时正文突然换行、滚动高度跳动。

## 代码证据

`node scripts/verify-to-bottom-gutter.mjs --self-test` 使用当前引擎版本的原始 chat CSS 夹具和真实 Chromium 排版，
覆盖 360×796、600×1067、1600×900，输入区高度 128/220，距底 80/120/160/200/260/320/400px。
断言按钮与每个正文块无相交、间隔至少 8px、触区至少 44px、无水平溢出、卸载按钮不改正文尺寸和滚动高度。
同一页面关闭新增样式后，每组都必须复现遮挡，六组负控防止假绿。

本地结果：102 条真实浏览器几何断言通过，含六组原 CSS 负控。
这属于代码层回归，不代替已安装 APK 的 CDP 与 ADB 用户层验收。
