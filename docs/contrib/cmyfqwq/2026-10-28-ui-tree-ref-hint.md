# id 解析失败的提示把「形态用错」误报成「页面已变化」

## 现象

`resolveRef`（`plugins/dsh-android-manage/src/ui-tree.ts`）的缓存键 `byId` 是**剪枝后重编号**的
`n0`/`n1`…，而壳侧原始 id 是 `"0"`/`"0.1"` 这种。模型若用原始形态引用，旧提示一律说：

```
id "0.1" 不在最近一次取树结果中（页面可能已变化）——请重新取树（android_ui_dump 或 android_ui_tree）
```

但**重新取树后 `id:0.1` 仍然找不到**（缓存键永远是 `nN`）⇒ 死循环引导，同时掩盖了真正的修法
（直接用本次取树返回的 `nN` 形态）。

探针（桩 `snapshot` 返回两个节点，dump 后用 `id:0.1` 点）：

```
dump 返回的 ref 形态: [ 'n0', 'n1' ]
id:0.1     -> FAIL | id "0.1" 不在最近一次取树结果中（页面可能已变化）——请重新取树（…）
id:n1      -> ok   | 已点击 n1「确定」…
n1         -> ok   | 已点击 n1「确定」…
id:00      -> FAIL | id "00" 不在最近一次取树结果中（页面可能已变化）…
id: 0.1    -> FAIL | id " 0.1" 不在最近一次取树结果中（页面可能已变化）…
```

对照 `text:` 路径就能看出差别：`text:确定` 命中了 n1，说明**缓存本身是好的**，问题只在这句文案把
两类完全不同的成因说成了同一类。

## 修法

失败文案给出**两种可能**，并把本次取树的真实 id 形态作为样例（取自 `nodes[0].id`，不写死）：

```
id "0.1" 不在最近一次取树结果中——两种可能：① id 形态用错（本次取树的 id 形如 n0，请直接用它，
而不是壳侧原始 id）；② 页面已变化（请重新取树 android_ui_dump / android_ui_tree）
```

与 #763（截图不得编造分辨率）、#745（未知值不得编造成 0）同族：**文案与真实状态必须同口径**，
否则模型会照着错误指引空转。

## 复验证据

| 用例 | 断言 |

| 正确形态回归护栏 | `id:n1` 仍命中，`node.text === '确定'` |

## 已知边界

1. 只改**提示文案**，命中语义一字未动（`id:n1` / 裸 `n1` / `text:` / `desc:` / `rid:` 行为不变）。
2. 同类提示里还有一处 `作用域 ${scopeId} 不在最近一次取树结果中`（`@nX` 后缀）,本轮未动——
   它的成因确实是「作用域 id 不存在」一种，没有把两类混说。
3. 文案里点名 `android_ui_dump` / `android_ui_tree` 两个工具，是因为两者产出的 ref 空间一致；
   若将来引入第三处取树来源需同步这句。
