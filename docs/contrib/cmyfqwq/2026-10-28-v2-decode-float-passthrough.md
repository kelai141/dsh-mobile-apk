# 控制协议 V2 解码器：整数列被浮点静默穿透（2026-10-28）

## 现象

给 `decodeV2` 喂一个**含小数**的列，它不会报错，而是返回一份"看起来正常"的节点表——
小数在每一处下游按整数语义被消费，于是值**变成另一个值**，而调用方毫不知情：

| 载荷改动 | 修前实测 | 后果 |
|---|---|---|
| `t=[0.5,-1]`（文本符号表下标） | `row0.text=""` | `S[0.5]` 取不到 ⇒ `?? ''` ⇒ **文本静默变空串** |
| `k=[0.5,-1]`（包名下标） | `pkg=""` | 同上，包名静默丢失 |
| `p=[-1,0.5]`（可操作祖先列） | `ancestor=[-1,0]` | 写进 `Int32Array` 被 ToInt32 截断 ⇒ **指向别的行** |
| `f=[1.9,0]`（位标志） | `clickable=true` | 位运算前 ToInt32 ⇒ `1.9` 被读成 clickable |
| `d=[0,1.5]`（深度） | `depth=1.5` | 预序父链按浮点比较 ⇒ 父子关系错乱 |
| `b[0]=1.5`（bounds） | `x=1.5, cx=51.5` | 坐标带小数 ⇒ `input tap` 落点偏移 |
| `scr=[100.5,200.5]`（屏幕基准） | `screen=100.5x200.5` | 归一化换算的基准带小数 |

同组口径的另一半：`gen` 有守卫而 `rot` 没有 —— `rot:"abc"` / `rot:NaN` / `rot:{}` 算出
`rotation=NaN` 并原样透出；`NaN` 不是合法 JSON ⇒ `JSON.stringify` 得到 `{"rotation":null}` ⇒
工具返回值在引擎侧被**整值拒绝**，模型拿不到任何数据（#204 / #258 同族）。

## 真因

```ts
const isIntArray = (v: unknown): v is number[] =>
  Array.isArray(v) && v.every((x) => typeof x === 'number' && Number.isFinite(x))
```

**名字承诺整数，实现只查有限数。** 这个判据被 `scr`、`b`、9 个列数组、`o` 共用，
于是"是不是整数"从来没有在入口被问过；只有 `o` 列在循环里**单独复查**了
`Number.isInteger(src)`（越界与严格递增检查顺带做了）——这恰好证明缺口已知，只是没推广到别的列。

为什么之前没被发现：既有坏载荷用例（`坏载荷一律失败关闭`）全部是**长度 / 缺列 / 越界**类，
**没有一个喂过浮点值**；而合法路径（壳侧 Kotlin `gen: Long` / `rotation: Int` / `width: Int`、
TS 编码器）产出的都是整数，所以症状在设计上"不该发生"，也就没人测。

严格说这不是"输入校验漏了一条"，而是**判据放错了层级**：整数性是列的属性，却分散在各个消费点
（`o` 复查一次、`Number(handle)` 一次、`Int32Array` 静默截断无数次），任何一处忘记复查就断裂。

## 修法

1. **判据提到唯一入口**：`isIntArray` 改用 `Number.isInteger`（`Number.isInteger` 已涵盖
   `typeof === 'number'`）。这样"某列忘了复查"在结构上不可能发生，而不是靠人记住。
2. **`gen` / `rot` 同口径**：两者都是壳侧整数元数据，都要求整数；`rot ?? 0` 让缺省与 `null`
   仍落到 0（保持既有兼容），只有"给了但不能解析成整数"才失败关闭。
3. **判据分叉时文案必须跟着分叉**：`scr` 与 `b` 原本写成 `!isIntArray(x) || length !== 期望`，
   一个浮点值会报成「b 长度必须为 4n=8（收到 8）」——长度明明是对的，模型会照着错误消息去改长度。
   类型与长度各自成条，两条错误各自指向真因。

## 为什么合法快照不受影响

收窄前先核对了生产者的静态类型，不是凭"应该不会发小数"：

- 壳侧 `ControlProtocolV2.kt:96-102`：`gen: Long` / `rotation: Int` / `width: Int` / `height: Int`；
- TS 编码器 `encodeV2` 的输入是 `EncRow`（`x/y/w/h` 取自 `parseBoundsToBox` 的整数解析）；
- 对照用例保留了全整数载荷（含 `0`、`-1` 哨兵、`rot` 的 0/90/180/270 与缺省）必须**原样通过**。

## 复验证据

- 探针（修前）：12 列浮点 + `rot` 4 种坏值全部被**接受**并产出错误值；`rotation=NaN` 序列化成 `null`。
- 探针（修后）：同样输入全部失败关闭，错误文案各自指向真因（`t 必须是整数数组` /
  `b 必须是整数数组（每行 x,y,w,h 四个整数像素）` / `rot 必须是整数（收到 abc）`）。
- 插件测试：`node --test test/*.test.mjs` ⇒ **105 例全绿**（原 101 + 新 4）。
- 变异反证（三条，均变红后复原）：
  1. `isIntArray` 改回 `Number.isFinite` ⇒ 「整数列含浮点」与「文案真因」2 例红；
  2. 删掉 `rot` 整数守卫 ⇒ 「gen / rot 必须是整数」1 例红；
  3. `b` 判据合并回 `!isIntArray || length` ⇒ 2 例红（含文案用例）。
- 设备验证：**未做**。本次是引擎侧解码器的更严输入校验（L2 桥协议面），需在发版候选时补真机三层；
  热推不适用（改的是插件源码，须重新打包）。
