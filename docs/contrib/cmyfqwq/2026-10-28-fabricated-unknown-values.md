# 未知值被编造成 0：同一处返回体里的两套口径（2026-10-28）

## 现象

契约在仓库里被反复写过：「**只在壳侧真回显时才带键，绝不编造默认值**（否则「没回显」看起来像「值为 0/x」）」
（`screen-fields.ts` 头注释、`coord-basis.ts`、`basisFields` 的注释都在讲同一件事）。但同一批返回体里
仍有两条路径在编造，且**与紧邻的守契约代码并排出现**——所以不是"没人知道规则"，而是规则没有落到同一处。

### A. 归一化坐标点击：编造坐标 0,0（探针实测文案）

```
已按归一化坐标 (0.500,0.500) 点击（无障碍通道，实际坐标 0,0，（基准未回显：壳侧版本较旧））；...
```

**同一句话里两套口径**：括号里的「基准未回显：壳侧版本较旧」是 `coordBasisNote` 如实报告，
而「实际坐标 0,0」是 `x: clicked.x ?? 0, y: clicked.y ?? 0` 编造出来的——壳侧根本没回这两个数。
模型据此会以为点在了屏幕左上角，而这恰恰是 #258 §5.1「误报成功」要治的那类错。

### B. `web_dump`：同一句里 `vw`/`vh` 报 `?`、`scrollY` 报 `0`

```
WebView DOM 快照：（视口 ?x?，滚动 0；命中 0 个可交互元素，返回 0 个）
```

`?` 表示"壳侧没给"，`0` 却是"确实滚到顶部"。在长列表场景里，模型会把"没回显"读成"已到顶"，
于是停止滚动——一个看不见的错判。

## 真因

两处都是 `?? 0` 的**兜底默认值跑到了语义位置**上：默认值本身没错（`offset ?? 0`、`fraction ?? 0.6`
这类参数默认是合理的），错在**把"未知"映射成某个具体值**。判据很简单——

> 这个字段的 `0` 是「真的等于 0」还是「不知道」？凡是后者，就必须缺席或显式未知标记。

A 的 `x/y` 是"壳侧换算后的实际落点"，`0` 是合法坐标（左上角）⇒ 与"未知"撞车；
B 的 `scrollY` 同理。而同一模板里 `vw/vh` 已经选了 `?`，说明正确做法就在旁边。

## 修法

1. **A**：新增 `clickedXY` —— 仅当 `x`/`y` 都是**有限数**时才成立；成立才 `...clickedXY` 带键，
   否则整键不发（schema 里 `x`/`y` 非 `required`，缺席合法）。文案同源：`clickedXY === null`
   时报「实际坐标 未回显」，不再写 0,0。顺带把非有限值一并拒掉（NaN/Infinity 不是合法 JSON，
   引擎 `{type:'number'}` 会整值拒绝，#204/#258 同族）。
2. **B**：`scrollY` 改成与 `vw/vh` 同一判据——有限数才显示数字，否则 `?`。
3. 两处都留了注释说明"为什么不给默认值"，并写清另一个字段的正确做法就在旁边，避免下次又改回去。

## 复验证据

- 探针（修前 → 修后）：
  - A：`x=0, y=0`、文案「实际坐标 0,0」 → `x/y` **缺席**、文案「实际坐标 未回显」；
  - B：`滚动 0` → `滚动 ?`（与 `视口 ?x?` 同口径）。
- 三条新用例（含**反向**）：未知时缺席 / 未知时报 `?` / **真回显时必须如实带出**
  （`x=540,y=1200`、`视口 412x915，滚动 204`）——最后一条防"为了拒未知把合法值一起丢掉"。
- `a11y-routing.test.mjs` 36 例全绿；插件全量 104 例全绿（本分支基于 main，例数与 #733 分支不同）。
- 变异反证：把 A 改回 `x: clicked.x ?? 0, y: clicked.y ?? 0` ⇒ 坐标用例红；把 B 改回 `滚动 ${data.scrollY ?? 0}` ⇒ 口径用例红。
- **未做设备验证**：改动是引擎侧返回体/文案组装（L1/L2 边界），需随发版候选补真机三层。
