# 预发布段参与版本比较（2026-11-04，issue #1365）

## 现象

rc / preview 用户收不到后续更新：`v0.14.2-rc.2` 与 `0.14.2-rc.1` 都归约成 `[0,14,2]`，
`isNewer` 逐位相等后直接 `return false` ⇒ 检查更新恒 `UpToDate`；同核心的正式版对 rc 用户
同样判「已是最新」。用户只能手装。

## 真因

比较口径只覆盖了「核心数字 + fx 修订链」，把**预发布段整段剥掉后当作不存在**。剥后缀本身
是对的（`v0.13.7-rc.1` 不能因为多一个数字组就比 `0.13.7` 大），但剥完就丢掉了「谁是 rc.2、
谁是 rc.1」这条信息——而它正是预发布用户之间唯一有意义的先后。

## 修法

核心数字比完且相等后，再比预发布段：

- 新增 `prereleaseOf(v)`：`-rc.2` → `("rc", [2])`、`-SN-1-13` → `("sn", [1,13])`、无白名单后缀 → `null`；
- `isNewer` 的收尾从「直接 false」改成四支：都无 → false；只有候选有 → false；只有当前有 → true；
  都有 → 先比族名、再逐位比数字（缺位补 0）；
- `fx-N` 仍**不**算预发布段（它走核心数字比较），修订链语义不变。

## 复验

`UpdateCheckerSuffixTest` 新增四组：同核心 rc 序号比较（含 rc.10 > rc.9 的数值比较）、
正式版高于同核心预发布、`prereleaseOf` 只认白名单、修订链语义不受影响。

- **Kotlin 单测未在本机跑**（无 Android SDK/Gradle，由 CI 执行）。本机给出「判据模型对照」：
  同一组输入下旧算法对 `rc.2 > rc.1`、`rc.10 > rc.9`、`正式版 > rc.1` 全返回 false，新算法返回
  true；`fx-3 > fx-2`、`rc.1 < 正式版` 两条回归不变。源码契约部分改前 3 条红、改后 3 条绿。
- `node scripts/check-kotlin-comments.mjs` → PASSED；`node scripts/check-code-map.mjs` → PASSED。
- **未做设备验证**：本机无模拟器。应用内更新的真机复验见 PR 验收卡。
