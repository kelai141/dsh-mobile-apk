# 0.14.9-preview 块J：悬浮球「隐藏」与贴边召回条

> 状态：**待 review；未做设备验证**。代码层（Kotlin 单测 + 静态门禁）已在本机跑绿；CDP 层与 ADB 用户层需要装包后在模拟器/真机上按 `AGENTS.md` §2.1 补——**进入发版候选前必须完成，PR 描述已显式标注**。
> 需求来源：真实使用反馈（球挡视野）→ 交互在实现前由用户在两选项中拍板：
> **在展开面板里加「隐藏」入口** → **球消失后屏幕边缘留一条半透明召回条，点它召回**。

## 1. 形态（达成了什么）

| 项 | 内容 |
|---|---|
| 入口 | 展开面板**顶行**（会话选择行）右端，`隐藏` 文字入口（`contentDescription="隐藏悬浮球"`，热区 44dp），与 `✕ 收起面板` 并列但语义不同 |
| 进入隐藏 | 面板收起 → **球窗与光环窗从 WindowManager 移除** → 按球的最后位置在**最近的水平边缘**留一条 8×44dp 半透明药丸条 |
| 退出隐藏 | 点召回条 → 收条 → 光环窗、球窗**按 F8 z 序**重新入窗 → 球落在条所在的那条边（与拖动钳制同边界） |
| 服务 | **不停**。探活 / MuxClient / live 流照常跑；召回时状态是最新的，不需要重建 |
| 持久化 | **无**（刻意不落盘）。隐藏是会话内临时动作，服务重启/进程重建即回位；要长期不可见用设置页开关 |
| 与开关的关系 | `OverlayController.isEnabled`（偏好 ∧ 权限 ∧ 实例在场）在隐藏态仍为 true——因为服务确实在场、召回条确实可见。这不是 ST-02 那种「显示开、事实不在」的不一致，见 §4 |

两个函数是全部行为面（都在 `OverlayRecall.kt`）：

- `internal fun recallStripPlacement(ballX, ballY, ballSize, stripW, stripH, screenW, screenH): IntArray`
  —— 球心在左半屏贴左缘（x=0）、否则贴右缘（x=screenW-stripW）；纵向与球心对齐后夹进 `[0, screenH-stripH]`。
- `internal fun recallBallPlacement(stripX, stripY, stripH, ballSize, margin, screenW, screenH): IntArray`
  —— 与上一条**同形**的选边表达式（保证「条在左边、球从右边冒出来」不可能发生）；夹取边界与
  `OverlayService.clampBallPos` **逐字一致**（召回后的球必须落在「拖动能到达的位置集合」里）。

## 2. 为什么是「移除窗口」，不是 alpha / GONE / NOT_TOUCHABLE

三种「留着窗口但看不见」的写法都被否掉了，这是本块最值得写下来的一条：

| 写法 | 死因 |
|---|---|
| `view.alpha = 0f` | overlay 窗口只要还在 WindowManager 里就**照样吃触摸**：屏上留一个 34dp 的**隐形触区**，它下面应用的手势被吞——正是 0.13.2「互吞」缺陷的同形复发（当时的根因也是「窗口比可视图形大」） |
| `visibility = View.GONE` | 同上（GONE 只是不画，窗口与命中区仍在） |
| 加 `FLAG_NOT_TOUCHABLE` | 要**改球窗的 flags**，而「球窗尺寸/标志全程不变」是 F8 的硬约束（见 `OverlayService.buildRoot` 注释：互吞与错位根治的依据）；改它等于动那条已根治互吞/错位的纪律。另外本块的判据是「球窗必须从窗口表里消失」（`dumpsys window`），只加 flag 满足不了它 |

**移除窗口**是唯一同时满足「真消失」与「零隐形触区」的做法。代价是必须处理窗口生命周期：

- 隐藏 → 召回要按 **F8 z 序**（先光环、后球）重新 `addView`；顺序写反 = 辉光整窗盖住球面
  （2026-09-05 真机实测过的回归）。这条顺序由 `CallSiteContractTest.recallReAddsTheHaloBeforeTheBallToKeepZOrder` 钉住。
- `onDestroy` 必须收条（残窗纪律，同 `report.hideReport()` / `panel.closePicker()`）。
- `onConfigurationChanged` 里隐藏态要提前返回：球/光环不在 WindowManager 里，
  `updateViewLayout` / `syncHalo` 对它们只会抛异常（被 try 吞掉，但那是噪声不是路径），
  真正的活是让条在新屏幕重新贴边（竖屏贴右缘的条转到横屏会整条悬在屏中间）。

| 面 | 落点 | 判据 |

| 入口 | `OverlayPanel.buildUnit`（`overlay-hide-entry`） | `CallSiteContractTest.theHideEntryLivesInThePanelAndCallsHideBall`（入口在场 + 点击走 `svc.hideBall()` + 换肤同步） |
| 隐藏 | `OverlayService.hideBall()`（`OverlayService.kt:415`） | `hidingRemovesBothWindowsInsteadOfFadingThem`（必须 `removeWindow(rootView)`/`removeWindow(haloView)`，且**不得**用 alpha/visibility 冒充） |
| 召回 | `OverlayService.recallBall()`（`OverlayService.kt:436`） | `recallReAddsTheHaloBeforeTheBallToKeepZOrder`（z 序 + 收条 + 复位光环） |

## 4. 明确不做（写死，别顺手改）

1. **隐藏态不落盘**。不新增 prefs 键、不在 `MainActivity.onResume` 里补隐藏。理由：隐藏是「我现在
   不想看到它」的**临时**动作，与设置页开关（持久化、停服务）是两种意图；持久化会让「球不见了、
   开关还是开」这种真正的 ST-02 不一致变成常态。要长期不可见 = 用设置页开关，那条路径才是持久的。
2. **不做手势隐藏**（双击球 / 长按球都不挂）。用户明确选了面板内的显式入口，而「收起面板」是面板上
   最高频的动作——把隐藏塞进长按等于给最高频动作挂上一个不可撤销的歧义（误触 = 球没了）。
3. **不新增图标资源**。`隐藏` 用文字入口（与状态行 `查看汇报` 同一先例），不为一个入口新建 drawable。
4. **不放宽触摸目标**。条高 44dp（`MIN_TOUCH_TARGET_DP`）；条宽 8dp 是刻意的「拉手」观感，
   窗口尺寸 = 可视尺寸（不留隐形边，见 §2）。
5. **隐藏期间不换提示通道**。球不在屏上时，AI 提问/权限审批仍只走通知面（`NotifyCenter`）；
   本块不新增「隐藏态专属提示」。这是「你主动要求静默」的必然结果，登记在 known-gaps。

## 5. 验收清单（三层，缺一层即未验收）

  `node scripts/check-kotlin-comments.mjs`、`node scripts/check-code-map.mjs` 必须绿；
  `node scripts/check-kotlin-test-count.mjs --update-baseline` 在一次**真跑**之后执行（基线只许升）。
- **CDP 层**：面板顶行出现 `隐藏` → 点击后 `dumpsys window` 里 **不再有球窗/光环窗**、
  出现召回条窗口（一条 8×44dp 的 overlay）→ 点条后球窗/光环窗回来、**光环在球之下**（z 序可用
  `dumpsys window` 的窗口顺序核对）。
- **ADB 用户实际体验层**：`input tap` 点 `隐藏`（竖屏 16416 / 横屏 16384 各一次 + 截图）；
  点条召回后**用拖动再验一次手感**（召回落点必须在可拖动区间内，不得先跳一下）；
  锁屏/旋转各一次（条在新屏幕重新贴边）；**边缘返回手势**在条上会被吞（条只有 8×44dp，
  与球窗同类的局部干涉，需人眼确认可接受）。

## 6. 已知风险 / 待真机确认

- 条**贴屏缘 x=0**，可能落在系统的边缘返回手势热区内（8dp 宽 × 44dp 高）。若真机上体感不好，
  把 `recallStripPlacement` 的贴边值改为 `edgeMarginPx` 即可（一行、纯函数、有测试）。
- 隐藏态下设备控制工具（`android_*`）执行时的自动化避让提示（`notifyAutoCollapsedForAutomation`）
  不会出现——它被 `svc.expanded` 门控，而隐藏态面板必然是收起的（行为正确，但没在真机走过）。
- **条只有 8dp 宽**（§4.4 刻意设计）：命中区 = 窗口 = 8×44dp，**真人点按手感未经设备验证**。
  2026-10-18 复核意见按仓内先例（S2-18 的 20×20dp 曾判「按不准」并改 44dp；`VdisplayFloat` 贴边把手
  22×64dp）建议加宽到 ≥22dp；**用户拍板保持 8dp 原样交付**，本条登记为待真机确认的风险。
  若真机手感不好：加宽 = 改 `OverlayRecall` 的条宽常量（窗口与可视同步改，别只改可视），
  贴边内缩 = 改 `recallStripPlacement` 的 `edgeMarginPx`（一行，有测试）。
