# 批量读取会话日志头

原版后端枚举并选取 generation，再逐个打开日志、读取第一帧并交给 Node Zstd 解压。探针使用 APK 安装的同一个服务，在隔离测试进程临时替换两个方法，比较原版、批量 JS 和 Rust 三组。三组都使用相同的并发上限 3；保留原版目录枚举、generation 选择、JSON 校验、版本判定、文件身份及结果组装。

批量 JS 复用一个 8 KiB 缓冲区，同步读取和解压，每处理 32 条让出一次事件循环。Rust 每次列表只启动一次 Android 原生进程，用同样的路径清单读取 Zstd 第一帧并返回原文。Rust 不加载 Termux 共享库，父进程仍是 APK 内的 Node。计时包含准备路径、启动原生进程、传输和原版服务剩余工作；Rust 子进程的 CPU 与 RSS 单独记录。

超出探针读取上限、无效 UTF-8、读取失败或帧异常都交回原版处理。控制样本包括正确首帧和后续事件帧、校验和错误、截断、魔数错误、多行首帧、缺文件和取消。正常语料每次列表必须得到相同的完整摘要，且批量分支必须命中每条会话。

2026-11-10，在隔离 Android API 35、主 ABI x86_64 的设备上，对同一批 512 条 Zstd 会话交替运行三组，每组先挂载新后端并列举一次，再复用后端列举。三组列表摘要一致；两个批量变体所有样本均命中 512 条，零回退。

| 实现 | 新后端 p50 | 复用后端 p50（范围） | 复用 CPU p50 | 复用 GC p50 | Node 结束 RSS p50 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原版 | 43.32 s | 28.40 s（24.94–43.69） | 23.60 s | 920 ms | 121 MiB |
| 批量 JS | 16.87 s | 12.15 s（5.73–18.87） | 10.69 s | 983 ms | 119 MiB |
| Rust 批量 | 9.15 s | 5.61 s（4.22–8.97） | 4.84 s | 552 ms | 104 MiB |

Rust 的 CPU 列包含父子两个进程；子进程报告的峰值 RSS 中位数为 61 MiB，与父进程的结束 RSS 不是同一时点。包含启动和传输的 Rust 批量步骤复用时 p50 为 1.89 秒，批量 JS 步骤为 7.31 秒。Rust 在本轮有额外收益，但样本只有三组，两个批量变体的时间范围重叠，不能推断真机能耗或整个 APK 冷启动。原始数据见 [512 条三路对照](evidence/avd-api35-x86_64-batch-512.json)。

复测：在隔离调试 APK 的缓存中并排放置 `baseline-device.mjs`、`batch-device.mjs` 和本 ABI 的 `dsh-session-header-probe`。在应用数据根用 APK 的 Node 执行 `baseline-device.mjs <已安装的@deepseek-ai目录> 512 zstd <原生探针路径>`。

批量读取扩大了枚举和单个文件读取间的时间窗。探针只处理独立、静止的测试语料；接入产品前必须在发布结果前重新核对 generation 和文件身份，出现变化时交回原版读取。还需覆盖并发写入、历史数据和取消，并在真实 WebUI 上测量交互延迟和进程常驻成本。
