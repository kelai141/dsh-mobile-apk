# DSH 文件补全原生探针

上游 `packages/context/file-reference-local/src/search.ts`（`66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`）为 WebUI 的 `@` 补全枚举工作区路径。无目录前缀的模糊查询会复用路径清单，但每次都要转换大小写、打分并排序。此探针对照 APK 内实际安装的 `@deepseek-ai/dsh-file-reference-local` 导出类；和已经调用 Rust ripgrep 的工具内容搜索是两条路径。

2026-11-09，隔离的 Android Studio AVD（API 35，主 ABI x86_64），APK 调试实例的应用 UID，Node 24.18.0。用同一棵合成目录（20,011 个文件，另有目录、符号链接和排除项）运行六组，三种实现的运行次序覆盖六种排列。每组先建新索引并查询一次，再做 8 轮共 104 次查询。文件系统缓存未清理。「新索引」不是 APK 或设备冷启动。13 个查询的首轮结果逐项对比路径、类型及顺序，包括无匹配、同分截断、中文、希腊语大小写、带点 I、表情字符和隐藏项。符号链接及排除目录未出现在结果中。

Rust 整组连同子进程启动和输出回传的墙钟时间中位数为 1619 ms（1354–3309）。每组只启动一次，不能推算为每次按键启动子进程也有收益。原始数据见 [x86_64 设备对照报告](evidence/avd-api35-x86_64.json)。NDK API 26 下两个 ABI 都已编译并核对 ELF LOAD 对齐为 16 KiB；此对照仅在 x86_64 上执行。

探针只覆盖默认设置下的裸模糊查询。优化 JS 复用原版目录遍历，和 Rust 一样预计算大小写、隐藏状态并避免全量排序（JS 用有界列表，Rust 用部分选择）。优化 JS 已拿到大部分热查询收益，且与 Rust 的热查询耗时范围重叠；Rust 的新索引优势值得在真实目录复测。当前保留原产品实现。后续若接入，需比较进程内调用或持久 worker 的延迟及 RSS，保留上游对配置、工作区、目录前缀、安全边界、取消和索引失效的处理，并在两种 ABI 的 WebUI 实测。文件名编码异常须交回上游实现处理。

复测时将交叉编译的二进制和 `compare-device.mjs` 复制到隔离调试 APK 的应用缓存。在应用数据根目录，用应用随包的 Node 执行脚本，传入探针二进制路径及已安装的 `@deepseek-ai/dsh-file-reference-local/lib/index.js`。脚本自己构建及清理合成目录，结果不一致时返回非零。
